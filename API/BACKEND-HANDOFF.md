# TripFlow. Интеграция C# backend с Python

Этот документ описывает рабочий сценарий для обсуждения с C#-разработчиком. Схема межсервисного обмена взята из `API/ARCHITECTURE.md`. Последний README уточняет, что для Python выбрана облачная модель DeepSeek. В обоих новых стендах используется `deepseek-flash`. Способ поиска и источники цен ещё выбираются. URL и JSON ниже служат рабочими примерами для согласования. [Архитектура](ARCHITECTURE.md#подбор-и-расчёт-бюджета) · [Актуальный README](README.md#модель-и-стенды-карточки)

## Сценарий от черновика до сметы

~~~mermaid
sequenceDiagram
    participant R as React
    participant C as C# backend
    participant P as Python API
    R->>C: Сохранить параметры и запустить подбор
    C->>C: Сохранить taskId и версию карточки
    C->>P: POST /v1/recommendations
    P-->>C: 202 Accepted
    loop События подбора по мере готовности
        alt Готов новый проверенный вариант
            P->>C: Callback recommendation.added
        else Завершился поиск отелей или мест
            P->>C: Callback target.finished
        end
        C-->>P: Подтверждение после записи
        R->>C: GET карточки
        C-->>R: Накопленные варианты и состояние каждого типа
    end
    opt Группе нужны дополнительные варианты
        C->>P: POST /v1/recommendations с новым taskId и исключениями
    end
    R->>C: Сохранить выбранный отель и места
    R->>C: Запустить расчёт бюджета
    C->>P: POST /v1/budget с актуальным выбором
    P-->>C: 202 Accepted
    P->>C: Итоговый callback сметы
    C->>C: Сохранить статьи и итог для версии карточки
    R->>C: GET карточки с бюджетом
    C-->>R: Смета и статус полноты
~~~

Python сохраняет задачу, получает данные, проверяет кандидатов и доставляет события. C# хранит карточку, её версию, выбор автора, исключения, очередь полученных вариантов и итоговый бюджет. React работает с карточкой через C# и показывает кандидатов по мере готовности. В архитектуре предусмотрен показ одного кандидата за раз из очереди C#. [Роли сервисов](ARCHITECTURE.md#ответственность-сервисов) · [Callback и завершение выдачи](ARCHITECTURE.md#callback-и-завершение-выдачи)

## Три маршрута межсервисного обмена

| Метод и рабочий путь | Направление | Назначение |
|---|---|---|
| `POST /v1/recommendations` | C# → Python | Первый подбор и догенерация. Можно запросить отели, места или оба типа. |
| `POST /v1/budget` | C# → Python | Оценка питания, городского транспорта, прочих расходов и резерва по актуальному выбору. |
| `POST /internal/tripflow/events` | Python → C# | Один настроенный HTTPS-адрес для всех событий. Путь приведён как предложение. |

Обе операции Python возвращают `202 Accepted` после сохранения задачи. Входящие запросы C# и обратная доставка используют отдельные ключи. C# настраивает адрес приёма событий. Для запросов с JSON предлагается `Content-Type: application/json`, для ключей — заголовки `X-API-Key` на стороне Python и `X-Callback-Key` на стороне C#. Для принятого callback предлагается `204 No Content`. [Подбор и бюджет](ARCHITECTURE.md#подбор-и-расчёт-бюджета) · [Доставка событий](ARCHITECTURE.md#callback-и-завершение-выдачи)

Рабочий пример тела `202` — `{"taskId":"rec-001","status":"accepted"}`. Статус готовности подбора и сметы меняется после соответствующих callback.

### Общие правила типов

Далее используются типы JSON Schema. **Обязательное** поле должно присутствовать. `null` допустим там, где он явно указан в столбце типа. Для необязательных полей смысл отсутствия указан в описании. Имена полей в новых структурах приведены в `camelCase`. Маршруты и события следуют архитектуре, а точные поля и ограничения для межсервисного обмена предложены для согласования.

#### TripContext

Общий объект `trip` в запросах к Python.

| Поле | Тип | Присутствие | Смысл и ограничения |
|---|---|---|---|
| `destinationId` | `string` | Обязательно | ID из общего справочника направлений, например `ru-moscow`. |
| `startDate` | `string` | Обязательно | Календарная дата в формате `YYYY-MM-DD`. |
| `endDate` | `string` | Обязательно | Календарная дата в том же формате, не раньше `startDate`. Ночи — разница дат. |
| `travelers` | `integer` | Обязательно | Положительное число путешественников. |
| `budgetRub` | `integer` | Обязательно | Положительная сумма в рублях на всю группу и всю поездку, включая резерв. |
| `preferences` | `string`, `null` | Обязательно | Текст пожеланий. `null` означает, что пожелания отсутствуют. |

#### Coordinates

`Coordinates` — объект с двумя обязательными полями `latitude` и `longitude` типа `number`. Широта допускает значения от −90 до 90, долгота — от −180 до 180.

#### Цена отеля

`price` у отеля — одно число в рублях за **всю группу и всё проживание на даты поездки**. Если источник даёт цену за ночь, номер или человека, Python приводит её к сумме на группу до отправки варианта. Если доступна лишь цена «от» и обоснованную оценку полной стоимости получить не удалось, передаётся `null`. Python хранит основание суммы у себя. C# сравнивает `price` с лимитом на отель и добавляет её в смету как ориентировочную стоимость проживания. [Единицы и ограничения цен в стенде](experiments/deepseek-web-trip/report.md#flash-с-веб-поиском)

| Поле | Тип | Присутствие | Смысл и ограничения |
|---|---|---|---|
| `price` | `integer`, `null` | Обязательно | Неотрицательная сумма в целых рублях за всю группу и все ночи. `null` означает неизвестную стоимость. |

#### AdmissionPriceQuote

| Поле `AdmissionPriceQuote` | Тип | Присутствие | Смысл и ограничения |
|---|---|---|---|
| `amountRub` | `integer` | Обязательно | Сумма в целых рублях для указанной единицы цены, неотрицательная. `0` используется для подтверждённой бесплатности. |
| `basis` | `string` | Обязательно | `person_admission` — одно посещение на человека, `group_admission` — одно посещение на группу. |
| `kind` | `string` | Обязательно | `source` — цена из источника, `estimate` — расчётная оценка. |
| `isFromPrice` | `boolean` | Необязательно | `true` для цены «от». При отсутствии поля используется `false`. |
| `sourceUrl` | `string`, `null` | Необязательно | HTTPS-ссылка на основание цены. Для цены из источника ссылка указывается здесь или находится в связанной записи объекта либо тарифа. |

Неизвестная цена посещения передаётся как `price: null`.

#### TaskAccepted и ошибки

| Объект | Поле | Тип | Присутствие и смысл |
|---|---|---|---|
| `TaskAccepted` | `taskId` | `string` | Обязательно. ID задачи из запроса C#. |
| `TaskAccepted` | `status` | `string` | Обязательно. Значение `accepted`. |
| `ErrorResponse` | `taskId` | `string`, `null` | Обязательно. ID задачи, если его удалось прочитать из отклонённого запроса. |
| `ErrorResponse` | `error` | `object` (`ErrorDetail`) | Обязательно. Ошибка до принятия задачи. |
| `ErrorDetail` | `code` | `string` | Обязательно. Машинный код. Каталог кодов согласуется отдельно. |
| `ErrorDetail` | `message` | `string` | Обязательно. Краткое описание причины. |
| `ErrorDetail` | `fields` | `object` | Необязательно. Ключи — пути вроде `trip.endDate`, значения — непустые массивы `string` с ошибками полей. |

Если Python отклоняет запрос до `202`, предлагается вернуть HTTP-ошибку с `ErrorResponse`. Сбой принятой задачи сообщается в callback с `error`, описанным ниже для каждого события.

### 1. Запрос рекомендаций

Пример для первичного подбора. C# отправляет параметры поездки и на каждый нужный тип задаёт число вариантов и доступный лимит, если он уже известен. Поле `maxTotalRub` в примере означает сумму на всю группу за все ночи для отеля и на одно групповое посещение для места. Для догенерации C# вызывает тот же маршрут с новым `taskId`, запрашивает только нужный тип и передаёт уточнение и исключения. При замене отеля или места C# высвобождает его стоимость при расчёте нового лимита. [Правила подбора](ARCHITECTURE.md#подбор-и-расчёт-бюджета)

| Поле `RecommendationsRequest` | Тип | Присутствие | Смысл и ограничения |
|---|---|---|---|
| `taskId` | `string` | Обязательно | Уникальный непустой ID, который создаёт C#. |
| `trip` | `object` (`TripContext`) | Обязательно | Актуальные параметры карточки. |
| `targets` | `object` | Обязательно | Как минимум один из ключей `hotels` и `attractions`. |
| `targets.hotels`, `targets.attractions` | `object` (`RecommendationTarget`) | Необязательны по отдельности | Если ключ отсутствует, подбор этого типа не запускается. |
| `RecommendationTarget.count` | `integer` | Обязательно | Положительное максимальное число вариантов для этого типа. |
| `RecommendationTarget.maxTotalRub` | `integer`, `null` | Обязательно | Неотрицательный лимит на один подходящий вариант в указанных выше единицах. `null` означает, что отдельный лимит ещё не задан. |
| `RecommendationTarget.refinement` | `string`, `null` | Необязательно | Дополнительное пожелание только для этого типа. Отсутствие или `null` означает подбор по общим пожеланиям. |
| `RecommendationTarget.excludedObjectIds` | `array` из `string` | Необязательно | Уникальные `objectId`, которые нужно исключить из выдачи. Отсутствие равнозначно пустому массиву. |

~~~json
{
  "taskId": "rec-001",
  "trip": {
    "destinationId": "ru-moscow",
    "startDate": "2027-06-10",
    "endDate": "2027-06-15",
    "travelers": 2,
    "budgetRub": 60000,
    "preferences": "Отель рядом с метро, музеи и прогулки"
  },
  "targets": {
    "hotels": { "count": 1, "maxTotalRub": 30000 },
    "attractions": { "count": 4, "maxTotalRub": null }
  }
}
~~~

При запросе следующего отеля с теми же параметрами поездки блок `targets` может выглядеть так. В исключения входят уже показанные и отклонённые объекты.

~~~json
{
  "hotels": {
    "count": 2,
    "maxTotalRub": 30000,
    "refinement": "Можно дальше от центра",
    "excludedObjectIds": ["hotel-boulevard"]
  }
}
~~~

### 2. События подбора

Python доставляет `recommendation.added` для каждого готового кандидата. `objectId` — стабильный ID объекта в каталоге TripFlow. C# связывает полученный вариант и его цену с конкретной карточкой. В примере показаны условный отель и цена за всю группу на даты поездки. Варианты точной структуры тарифа и цены обсуждаются отдельно. [События подбора](ARCHITECTURE.md#callback-и-завершение-выдачи) · [Идентификация объектов](ARCHITECTURE.md#постоянный-каталог-объектов)

| Общее поле callback | Тип | Присутствие | Смысл и ограничения |
|---|---|---|---|
| `taskId` | `string` | Обязательно | ID принятой задачи. |
| `seq` | `integer` | Обязательно | Порядковый номер события внутри задачи, начиная с 1. При повторной доставке сохраняется. |
| `event` | `string` | Обязательно | `recommendation.added`, `target.finished` или рабочее имя `budget.finished`. Значение определяет остальные поля. |

| Дополнительное поле | Тип | Присутствие | Смысл и ограничения |
|---|---|---|---|
| `target` | `string` | Обязательно в `recommendation.added` и `target.finished` | `hotels` или `attractions`, один из запрошенных типов. |
| `candidate` | `object` (`Candidate`) | Обязательно в `recommendation.added` | Один готовый объект указанного типа. |
| `status` | `string` | Обязательно в `target.finished` | Предложение для enum: `succeeded` — выдача завершена, включая пустую, `partial` — найдена часть вариантов, `failed` — поиск завершился с ошибкой без пригодной выдачи. |
| `sentCount` | `integer` | Обязательно в `target.finished` | Число событий `recommendation.added` для этого типа в рамках задачи, без учёта повторов доставки. Может быть `0`. |
| `hasMore` | `boolean`, `null` | Обязательно в `target.finished` | Результат проверки наличия следующих вариантов. При неполном поиске используется `null`, когда наличие следующих вариантов неизвестно. |
| `error` | `object` (`ErrorDetail`) | При `failed` обязательно, при `partial` необязательно | Причина сбоя или неполного поиска. |

#### Candidate

| Поле | Тип | Присутствие | Смысл и ограничения |
|---|---|---|---|
| `objectId` | `string` | Обязательно | Стабильный ID объекта из каталога Python. |
| `name` | `string` | Обязательно | Название подтверждённого отеля или места. |
| `address` | `string`, `null` | Обязательно | Адрес, если известен. |
| `coordinates` | `object` (`Coordinates`), `null` | Обязательно | Координаты, если установлены. |
| `imageUrl` | `string`, `null` | Обязательно | HTTPS-ссылка на изображение, если доступно. |
| `sourceUrl` | `string` | Обязательно | HTTPS-ссылка на источник сведений об объекте. |
| `price` | `integer`, `null` для отеля. `object` (`AdmissionPriceQuote`), `null` для места | Обязательно | Отель — сумма за всё проживание группы. Место — цена одного посещения с указанием единицы. |
| `description` | `string`, `null` | Необязательно | Краткое описание на основе источников. |
| `recommendationReason` | `string`, `null` | Необязательно | Краткое объяснение, почему вариант подходит под пожелания. |
| `stars` | `integer`, `null` | Необязательно для отеля | Звёздность от 1 до 5, если подтверждена. |
| `category` | `string`, `null` | Необязательно для места | Категория, например «Музей». |
| `tariff` | `object` (`TariffSnapshot`), `null` | Необязательно для отеля | Данные конкретного тарифа, если найдены. |

Для `target: "attractions"` в `candidate` всегда присутствуют `imageUrl`, `coordinates` и `address`. Каждое поле независимо принимает `null`, если у источников нет подтверждённых сведений.

~~~json
{
  "taskId": "rec-001",
  "seq": 1,
  "event": "recommendation.added",
  "target": "hotels",
  "candidate": {
    "objectId": "hotel-boulevard",
    "name": "Бульварный дом",
    "address": null,
    "coordinates": { "latitude": 55.765, "longitude": 37.638 },
    "imageUrl": null,
    "sourceUrl": "https://example.org/hotels/boulevard",
    "price": 27000
  }
}
~~~

`target.finished` приходит отдельно для каждого запрошенного типа, в том числе при пустой выдаче. Например, ниже отели завершились раньше достопримечательностей. Номер `seq` относится ко всей задаче.

~~~json
{
  "taskId": "rec-001",
  "seq": 2,
  "event": "target.finished",
  "target": "hotels",
  "status": "succeeded",
  "sentCount": 1,
  "hasMore": true
}
~~~

Пример следующего события с достопримечательностью в той же задаче. Данные в примере условные.

~~~json
{
  "taskId": "rec-001",
  "seq": 3,
  "event": "recommendation.added",
  "target": "attractions",
  "candidate": {
    "objectId": "place-museum",
    "name": "Городской музей",
    "category": "Музей",
    "imageUrl": "https://example.org/images/city-museum.jpg",
    "coordinates": { "latitude": 55.741, "longitude": 37.62 },
    "address": "Москва, Музейная улица, 10",
    "sourceUrl": "https://example.org/places/city-museum",
    "price": { "amountRub": 900, "basis": "person_admission", "kind": "estimate" }
  }
}
~~~

Пока поиск идёт, при пустой очереди C# показывает ожидание. Когда очередь закончилась, `hasMore: true` означает, что есть следующий подходящий вариант, `false` — поиск исчерпан, `null` — результат по дополнительным вариантам пока неизвестен. В последнем случае интерфейс может предложить повторный поиск. [Состояние выдачи](ARCHITECTURE.md#callback-и-завершение-выдачи)

### 3. Запрос бюджета после выбора

C# фиксирует версию карточки и отправляет в Python параметры поездки, выбранный отель с конкретным тарифом и включёнными услугами, выбранные места и имеющиеся цены. Подтверждение завтрака должно относиться к тарифу или нужным дням. Сведения общего уровня об отеле сами по себе не дают оснований вычитать завтрак из сметы. [Правила бюджета](ARCHITECTURE.md#подбор-и-расчёт-бюджета) · [Пример проверки тарифа](experiments/deepseek-flash/README.md#отдельные-этапы)

| Поле `BudgetRequest` | Тип | Присутствие | Смысл и ограничения |
|---|---|---|---|
| `taskId` | `string` | Обязательно | ID новой задачи расчёта. |
| `trip` | `object` (`TripContext`) | Обязательно | Снимок исходных параметров. |
| `selectedHotel` | `object` (`SelectedHotel`), `null` | Обязательно | Выбранный отель. `null` означает, что отель в расчёт не передан. |
| `selectedAttractions` | `array` из `SelectedAttraction` | Обязательно | Выбранные посещения. Пустой массив означает план без посещений. |

| Объект | Поле | Тип | Присутствие и смысл |
|---|---|---|---|
| `SelectedHotel` | `objectId` | `string` | Обязательно. ID отеля из каталога. |
| `SelectedHotel` | `price` | `integer`, `null` | Обязательно. Сохранённая сумма выбранного варианта за всю группу и все ночи. |
| `SelectedHotel` | `tariff` | `object` (`TariffSnapshot`) | Обязательно. Сведения о выбранном тарифе и включённых услугах. |
| `TariffSnapshot` | `name` | `string`, `null` | Обязательно. Название тарифа, если известно. |
| `TariffSnapshot` | `includedServices` | `array` из `IncludedService` | Обязательно. Услуги, проверенные для тарифа. Пустой список допустим. |
| `IncludedService` | `service` | `string` | Обязательно. Ключ услуги. В примере `breakfast`. |
| `IncludedService` | `status` | `string` | Обязательно. `confirmed`, `contradicted` или `unknown`. Смету уменьшает только подтверждённое включение. |
| `IncludedService` | `dates` | `array` из `string`, `null` | Обязательно. Даты в формате `YYYY-MM-DD`. Для `confirmed` значение `null` означает подтверждение на весь соответствующий период тарифа. |

### 4. Итоговый callback бюджета

Рабочее имя события в примере — `budget.finished`. Python возвращает дополнительные расходы на всю группу за поездку. C# суммирует их с проживанием и билетами по тому выбору, к которому привязана задача. В примере итог **54 000 ₽** получается из **27 000 ₽** за отель, **1 800 ₽** за два билета и **25 200 ₽** дополнительных расходов. Остаток — **6 000 ₽**. Если у выбранного места цена неизвестна, C# показывает известную сумму и помечает смету как неполную. [Смета и версия карточки](ARCHITECTURE.md#подбор-и-расчёт-бюджета)

| Дополнительное поле `budget.finished` | Тип | Присутствие | Смысл и ограничения |
|---|---|---|---|
| `status` | `string` | Обязательно | `succeeded` или `failed`. Успешная оценка дополнительных расходов допускает неполную итоговую смету C#, если отсутствуют цены выбранных объектов. |
| `expenses` | `object` (`Expenses`), `null` | Обязательно | При `succeeded` передаётся объект, при `failed` — `null`. |
| `error` | `object` (`ErrorDetail`) | Обязательно при `failed` | Причина сбоя. |

Все поля `Expenses` обязательны. Суммы — неотрицательные целые рубли на всю группу и поездку.

| Поле `Expenses` | Тип | Смысл |
|---|---|---|
| `foodTotalRub` | `integer` | Питание с учётом подтверждённых включений тарифа. |
| `localTransportTotalRub` | `integer` | Городской транспорт. |
| `otherExpensesTotalRub` | `integer` | Прочие траты, исключая уже учтённые статьи. |
| `reserveTotalRub` | `integer` | Резерв на поездку. |

~~~json
{
  "taskId": "budget-001",
  "seq": 1,
  "event": "budget.finished",
  "status": "succeeded",
  "expenses": {
    "foodTotalRub": 14400,
    "localTransportTotalRub": 4800,
    "otherExpensesTotalRub": 0,
    "reserveTotalRub": 6000
  }
}
~~~

Пример завершившейся с ошибкой бюджетной задачи. Код в примере условный.

~~~json
{
  "taskId": "budget-002",
  "seq": 1,
  "event": "budget.finished",
  "status": "failed",
  "expenses": null,
  "error": { "code": "BUDGET_ESTIMATE_FAILED", "message": "Не удалось рассчитать дополнительные расходы" }
}
~~~

Для одной задачи подбора число callback зависит от количества готовых кандидатов и числа запрошенных типов. Бюджетная задача завершается одним итоговым событием.

## Версии и повторы

1. C# до отправки связывает `taskId` с версией карточки и снимком входных данных. Для сметы снимок включает выбранный отель, тариф и места.
2. Python сохраняет каждое событие перед отправкой. При повторной доставке остаются прежние `taskId` и `seq`. События одной задачи идут по порядку.
3. C# записывает событие и результат его применения, затем подтверждает доставку. Повтор того же `(taskId, seq)` подтверждается без повторной записи кандидата. Результат по устаревшей версии не меняет актуальную карточку.
4. Повтор запроса с тем же `taskId` и теми же данными возвращает прежний статус приёма. Для пересчёта по изменившемуся выбору или подбора по новым параметрам C# создаёт новую задачу. При временном сбое доставки событие остаётся у Python до повтора.

Подробности подтверждения, таймауты и обработка частичного подбора согласуются при реализации. [Порядок и повторы доставки](ARCHITECTURE.md#callback-и-завершение-выдачи)

## Контракты React → C#

`{dashboard}` означает `/api/dashboards/{dashboardId}`, `{card}` — `{dashboard}/cards/{cardId}`. Оба параметра пути — строки в формате UUID. В маршрутах текущего backend используются существующие DTO. Поля для подбора и бюджета ниже — предлагаемые расширения. [Маршруты карточек](../Backend/Dashboards.cs#L22) · [Состояние backend](../Backend/README.md#проверка-через-swagger)

| `POST {dashboard}/cards` | `TripInput` | `201`, `TripCardView` | Есть |
| `GET {card}` | Без тела | `200`, `TripCardView` | Есть, предлагается расширить ответ |

React может опрашивать `GET {card}` во время подбора и расчёта. После редактирования параметров или выбора старая смета теряет актуальность. Актуальный расчёт запускается через `POST {card}/budget`.

### TripInput и DestinationView

`TripInput` использует поля `TripContext`. В текущем запросе к C# `preferences` можно опустить или передать как `null`. Непустой текст ограничен 2 000 символами после обрезки пробелов. В сохранённом `TripCardView.trip` поле `preferences` присутствует. Поле `hotelBudgetLimitRub` предлагается добавить к `TripInput` отдельно: необязательное, тип `integer` или `null`, положительный максимум в рублях на всю группу за проживание. Пустое значение означает автоматический ориентир, когда для него достаточно данных. [Валидация карточки](../Backend/Dashboards.cs#L222)

### RecommendationQueueView и BudgetView

|---|---|---|---|

## Что ещё согласовать

- Точный формат `trip` и направления, структуру тарифа и правила подтверждения цен. Для отеля сумма уже относится ко всему проживанию группы. Способ поиска и получения тарифов уточняется по результатам стендов. [Исследование вариантов поиска](experiments/deepseek-web-trip/report.md#что-проверить-перед-интеграцией)
- Как задавать лимиты при первом подборе, пока смета ещё не рассчитана. `maxTotalRub` показывает возможное место для ручного лимита на отель, если его передал автор карточки.
- Итоговые JSON-схемы, HTTP-статусы, ошибки, таймауты, подтверждение и повторы событий. Условные адреса и имена полей в примерах следует уточнить с C#-разработчиком.
- Правила публикации при неполной смете, отсутствии отеля и пустом списке мест.
