# Инструкции для работы в API

Этот файл дополняет корневой `AGENTS.md` и действует для файлов внутри `API/`. Если инструкции расходятся, соблюдай более конкретное ограничение этого файла для работы в `API/`, сохраняя общий продуктовый контекст корневого файла.

## Границы изменений

- Рабочая область — каталог `API/`. Создавай, редактируй и удаляй файлы только внутри него.
- Не изменяй файлы и каталоги вне `API/`, включая корневые файлы, `Frontend/` и каталоги backend. Не перемещай файлы между этими областями.
- Не исследуй содержимое `Frontend/` и backend-каталогов без конкретной необходимости для текущей задачи. Если такая необходимость возникла, ограничься чтением минимально нужных файлов; ничего там не меняй.
- Общий `AGENTS.md` и другие документы проекта используй как контекст. Не редактируй их в рамках работы над API без прямой просьбы пользователя.
- Если задача невозможно выполнить, не выходя за эти границы, объясни причину и предложи вариант, который остаётся внутри `API/`.

## Git и коммиты

- Никогда не создавай коммиты самостоятельно — независимо от того, насколько закончена работа.
- Не выполняй команды, которые фиксируют изменения в истории Git. Оставь изменения в рабочем дереве для просмотра и коммита пользователем.

## Договорённости о географии и качестве данных — 28.10.2026

- MVP ориентирован в первую очередь на русскоязычную аудиторию и поездки по России. В архитектуре данных сохранить возможность добавления других стран и разных поставщиков по стране/региону. Не считать мировое покрытие обязательным для MVP.
- Полнота данных зависит от направления. При отображении различаются цена объекта из источника, расчётная оценка и неизвестная стоимость. Наличие суммы у источника не доказывает её актуальность для дат поездки.
- Городская/региональная оценка проживания показывается отдельно от цены конкретного отеля. Сохранять область применимости и период исходных данных; не выдавать региональную статистику за цену выбранного объекта.
- Отсутствующая цена билета остаётся `null`; ноль означает только подтверждённую бесплатность. Ориентировочная общая сумма расходов на посещения может рассчитываться отдельно.
- Для работы без запроса к источнику на каждый расчёт допустим локальный справочник реальных статистических ставок с происхождением, периодом и единицами. Это справочные данные, а не пользовательское состояние backend.
- Исследования Russhotels и Росстата дали реальные денежные ориентиры для российских направлений. Малые успешные выборки не являются гарантией полного покрытия России, свежести каждого тарифа или SLA поставщика. Проверять точный населённый пункт/координаты: строковый поиск источника может возвращать одноимённые или похожие места.

## Договорённости о контракте — 28.10.2026

- Для входящих запросов используется API key клиента, для callback — отдельный callback key в заголовке `X-Callback-Key`. Клиент задаёт callback key при настройке доступа; Python хранит его привязку к API key клиента, а принимающий backend проверяет ключ до обработки результата.
- В Markdown-контракте у каждого поля отдельно описываются тип и содержание. Типы обозначаются значениями `type` из JSON Schema, с явным указанием допустимого `null`, типов вложенных полей и элементов массивов.
- Полная генерация может завершиться успешно с пустыми списками отелей и/или достопримечательностей, если сформирована необходимая бюджетная основа. Отсутствие пригодных данных для обязательной категории расходов после предусмотренных попыток и резервных источников приводит к ошибке задачи. Общие ставки остаются отдельно от цен конкретных объектов.
- `hasMore` описывает дополнительные варианты сверх полученной выдачи: `true` — дополнительный подходящий кандидат найден, `false` — поиск завершён и дополнительных кандидатов нет, `null` — поиск остался неполным после предусмотренных попыток. При `false` полученная выдача используется до исчерпания, затем догенерация по тем же параметрам не вызывается. При `null` повторный поиск инициирует пользователь через догенерацию с новым `taskId`.
- Бюджет при полной генерации — целевой ориентир с мягкой нижней границей и предпочтительным верхним допуском. Превышение допуска не является само по себе ошибкой: возвращаются наиболее доступные подходящие варианты. Backend показывает разницу с целевым бюджетом, включая превышение в пределах допуска. Проценты диапазона пока не согласованы.

## Договорённости об источниках — 29.10.2026

- Краткий состав внешнего стека описан в `EXTERNAL_APIS.md`: основной стек включает также справочные источники и необязательное обогащение, без требования вызывать их на каждую генерацию.
- Для основных данных стремиться к полной или близкой к полной обеспеченности поддерживаемых направлений; не превращать это требование в утверждение о доказанном покрытии поставщиков. Неполнота дополнительных сведений допустима.
- Остальные перспективные источники описывать как варианты для рассмотрения после запуска основного стека.

## Договорённости о догенерации и ценах — 30.10.2026

- Догенерация возвращает альтернативы одного целевого типа и не меняет метаданные, общие оценки расходов или выбор пользователя. `refinement` уточняет исходные предпочтения и имеет приоритет при противоречии пожеланий к целевому типу. Поиск завершён без новых вариантов — успешный пустой результат с `hasMore: false`; ошибка операции возвращается с `result: null` и не меняет прежний `hasMore`.
- `optionBudgetRub` — предел стоимости нового выбора для всей группы. Для проверки и итогового расчёта используется `price.amountRub`, если он не `null`, иначе `price.estimatedRub`. Оба поля nullable; у возвращаемого отеля хотя бы одно заполнено. Достопримечательности с обеими суммами `null` допускаются без подтверждения соответствия лимиту; при выборе их стоимость не включается в итог, который отображается как неполный.
- Поле отеля `stars` содержит `1`–`5` или `null`; внешнее `0` передаётся как `null`. Внутри обработки явно известная категория «без звёзд» отличается от неизвестной категории и может использоваться для подходящей справочной оценки. Не назначать неизвестной категории автоматически дешёвую ставку.
- `position` — порядок с `1` внутри отдельной выдачи; общей очередью управляет backend.
- В MVP используется фиксированный локальный справочник ставок. Формулы оценок и детали ранжирования относятся к реализации, а не к межсервисному контракту.
- В контракте `quality` отсутствует и у кандидатов, и в `estimates`. Общие расходы передаются плоскими полями `foodTotalRub`, `localTransportTotalRub`, `otherExpensesTotalRub`, `reserveTotalRub`. Общие ставки проживания и посещений участвуют в предварительном расчёте до выбора конкретных объектов, затем заменяются расчётом выбранных объектов без двойного учёта.
- Достопримечательности имеют nullable-поле `category` для отображения и подбора подходящей справочной ставки. Обоснованная оценка по категории возвращается в `price.estimatedRub`; при недостатке данных допускается `null`.
- Для общих ставок `scope` имеет только значения `city`, `region`, `country` с последовательным переходом к более широкому пригодному ориентиру; `country` — последний резерв. Указывается фактический уровень исходных данных.
- Цена проживания в контракте — ориентировочные расходы одного путешественника за ночь без обещания отдельной комнаты. Для исходной цены сначала рассматривается размещение одного человека, затем минимальная пригодная альтернатива для проживания одного человека; по числу кроватей цена автоматически не делится.
- Ночи проживания — разница дат; питание и остальные ежедневные расходы учитывают обе даты включительно. Положительные дробные суммы после приведения к рублям округляются вверх до целого рубля, целые суммы сохраняются.
- Обязательные денежные оценки `estimates` не допускают `null`; невозможность получить пригодную оценку приводит к ошибке генерации. Ноль не подменяет отсутствие расчёта. Неполный итог дополнительно выделяется помимо общей оговорки об ориентировочности.
