# Инструкции для работы в API

Этот файл дополняет корневой `AGENTS.md` и действует для файлов внутри `API/`. Если инструкции расходятся, соблюдай более конкретное ограничение этого файла для работы в `API/`, сохраняя общий продуктовый контекст корневого файла.

## Границы изменений

- Рабочая область — каталог `API/`. Создавай, редактируй и удаляй файлы только внутри него.
- Не изменяй файлы и каталоги вне `API/`, включая корневые файлы, `Frontend/` и каталоги backend. Не перемещай файлы между этими областями.
- Не исследуй содержимое `Frontend/` и backend-каталогов без конкретной необходимости для текущей задачи. Если такая необходимость возникла, ограничься чтением минимально нужных файлов; ничего там не меняй.
- Общий `AGENTS.md` и другие документы проекта используй как контекст. Не редактируй их в рамках работы над API без прямой просьбы пользователя.
- Если задача невозможно выполнить, не выходя за эти границы, объясни причину и предложи вариант, который остаётся внутри `API/`.

## Git и коммиты

- Никогда не создавай коммиты самостоятельно — независимо от того, насколько закончена работа.
- Не выполняй команды, которые фиксируют изменения в истории Git. Оставь изменения в рабочем дереве для просмотра и коммита пользователем.

## Требования и технические решения

- Считай корневой `AGENTS.md`, README и требования MVP контекстом проекта, но не выдавай предварительные идеи за утверждённые требования.
- При реализации отделяй подтверждённые требования от открытых решений. Если неясность существенно влияет на контракт API, модель данных, поведение или границы сервисов, задай пользователю конкретный вопрос; независимую часть работы продолжай.
- Соблюдай существующие структуру и соглашения проекта в `API/`. Перед изменением разберись в относящихся к задаче файлах и не проводи несвязанный рефакторинг.
- Внешние данные и результаты AI должны оставаться проверяемыми: не представляй сгенерированные моделью отели, места или другие реальные объекты как подтверждённые данные источника.

## Итоговое объяснение

После выполнения каждой задачи кратко объясни ответом в чате, без создания отдельного отчётного файла:

1. Что изменено и где.
2. Как это работает и почему выбрано такое решение.
3. Какие выводы, ограничения или незакрытые вопросы остались.
4. Что было проверено и каков результат. Не утверждай, что проверка выполнена, если её не запускал.

Дополняй этот файл новыми устойчивыми договорённостями по мере того, как пользователь их формулирует.
