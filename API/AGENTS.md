# Инструкции для работы в API

Этот файл дополняет корневой `AGENTS.md` и действует для файлов внутри `API/`. Если инструкции расходятся, соблюдай более конкретное ограничение этого файла для работы в `API/`, сохраняя общий продуктовый контекст корневого файла.

## Границы изменений

- Рабочая область — каталог `API/`. Создавай, редактируй и удаляй файлы только внутри него.
- Не изменяй файлы и каталоги вне `API/`, включая корневые файлы, `Frontend/` и каталоги backend. Не перемещай файлы между этими областями.
- Не исследуй содержимое `Frontend/` и backend-каталогов без конкретной необходимости для текущей задачи. Если такая необходимость возникла, ограничься чтением минимально нужных файлов; ничего там не меняй.
- Общий `AGENTS.md` и другие документы проекта используй как контекст. Не редактируй их в рамках работы над API без прямой просьбы пользователя.
- Если задача невозможно выполнить, не выходя за эти границы, объясни причину и предложи вариант, который остаётся внутри `API/`.

## Git и коммиты

- Никогда не создавай коммиты самостоятельно — независимо от того, насколько закончена работа.
- Не выполняй команды, которые фиксируют изменения в истории Git. Оставь изменения в рабочем дереве для просмотра и коммита пользователем.

Проектная документация хранится в `API/docs/`, исследовательские материалы — в `API/docs/research/`. Сгенерированные отчёты и исходные данные остаются рядом со скриптами экспериментов.

Рабочие JSON-схемы и HTTP-маршруты для согласования с командой приведены в [handoff](docs/BACKEND-HANDOFF.md), примеры поведения — в [сценариях](docs/SCENARIOS.md), результаты проверок данных — в [обзоре источников](docs/EXTERNAL_APIS.md). Направления хранятся в [общем справочнике](../shared/data/destinations.json).
- Считай корневой `AGENTS.md`, README и требования MVP контекстом проекта, но не выдавай предварительные идеи за утверждённые требования.
- При реализации отделяй подтверждённые требования от открытых решений. Если неясность существенно влияет на контракт API, модель данных, поведение или границы сервисов, задай пользователю конкретный вопрос; независимую часть работы продолжай.
- Соблюдай существующие структуру и соглашения проекта в `API/`. Перед изменением разберись в относящихся к задаче файлах и не проводи несвязанный рефакторинг.

## Договорённости о географии и качестве данных — 28.10.2026

- MVP ориентирован в первую очередь на русскоязычную аудиторию и поездки по России. В архитектуре данных сохранить возможность добавления других стран и разных поставщиков по стране/региону. Не считать мировое покрытие обязательным для MVP.
- Полнота данных зависит от направления. При отображении различаются цена объекта из источника, расчётная оценка и неизвестная стоимость. Наличие суммы у источника не доказывает её актуальность для дат поездки.
- Городская/региональная оценка проживания показывается отдельно от цены конкретного отеля. Сохранять область применимости и период исходных данных; не выдавать региональную статистику за цену выбранного объекта.
- Отсутствующая цена билета остаётся `null`; ноль означает только подтверждённую бесплатность. Ориентировочная общая сумма расходов на посещения может рассчитываться отдельно.
- Для работы без запроса к источнику на каждый расчёт допустим локальный справочник реальных статистических ставок с происхождением, периодом и единицами. Это справочные данные, а не пользовательское состояние backend.
- Исследования Russhotels и Росстата дали реальные денежные ориентиры для российских направлений. Малые успешные выборки не являются гарантией полного покрытия России, свежести каждого тарифа или SLA поставщика. Проверять точный населённый пункт/координаты: строковый поиск источника может возвращать одноимённые или похожие места.

## Договорённости об интеграции — 22.11.2026

- React опрашивает C# через `GET {card}` во время подбора и расчёта сметы. C# хранит статусы и результаты карточки. React прекращает опрос после завершения или закрытия экрана.
- Python обрабатывает принятый запрос в фоне без отдельной очереди генерации. Каждая задача завершается одним callback. Подбор возвращает пакет всех найденных вариантов запрошенных типов. Смета запускается отдельно по сохранённому выбору.
- C# связывает `taskId` с актуальной версией карточки. Python сохраняет итог перед отправкой и повторяет тот же итог при временном сбое. C# подтверждает приём после записи и применяет результат один раз. Сроки, интервал polling и форматы ошибок уточняются при интеграции.
- Для входящих запросов используется API key клиента, для callback — отдельный ключ в заголовке `X-Callback-Key`. Адрес и ключ callback настраиваются на стороне Python для клиента, а C# проверяет ключ до обработки результата.
- В таблицах схем у каждого поля отдельно описываются тип и содержание. Типы обозначаются значениями `type` из JSON Schema, с явным указанием допустимого `null`, типов вложенных полей и элементов массивов.
- Для основной интеграции рассматривается прямой вызов DeepSeek с сервера Python. LM Studio остаётся дополнительным вариантом. Способ веб-поиска и источники цен ещё выбираются.

## Договорённости об источниках — 29.10.2026

- Кандидаты на источники и результаты их испытаний описаны в [обзоре источников](docs/EXTERNAL_APIS.md). Справочные сведения можно готовить заранее, а дополнительные данные запрашивать при необходимости.
- Для основных данных стремиться к полной или близкой к полной обеспеченности поддерживаемых направлений; не превращать это требование в утверждение о доказанном покрытии поставщиков. Неполнота дополнительных сведений допустима.
- Остальные перспективные источники описывать как варианты для рассмотрения после запуска основного стека.

## Подбор, цены и смета — 22.11.2026

- Догенерация запрашивает один тип через тот же маршрут, что и первичный подбор. `refinement` имеет приоритет над общими пожеланиями для этого типа. Новый пакет добавляется к сохранённым вариантам, действующий выбор остаётся за пользователем.
- Пустой завершённый поиск успешен. `hasMore: true` означает, что найден ещё один подходящий кандидат, `false` — что поиск исчерпан, `null` — что наличие дополнительных кандидатов неизвестно. При `null` пользователь может повторить поиск с новым `taskId`.
- Лимит `maxTotalRub` задаётся на группу. Для отеля он относится ко всем ночам, для места — к одному посещению всей группой. Размер бюджетных допусков и источники цен уточняются. Общие статистические ставки остаются основанием оценки отдельно от цен объектов.
- Цена отеля приводится к сумме за всё проживание группы. Цена посещения содержит сумму и единицу, либо `price: null`. При неизвестной цене выбранного объекта C# показывает неполный итог и сумму известных расходов. Ноль у цены означает подтверждённую бесплатность.
- Поле отеля `stars` содержит `1`–`5` или `null`. Внешнее `0` передаётся как `null`. Внутри обработки отличай явно известную категорию «без звёзд» от неизвестной категории.
- Ночи проживания — разница дат. Питание и остальные ежедневные расходы учитывают обе даты включительно. Положительные дробные суммы после приведения к рублям округляются вверх.
- Смета Python содержит `foodTotalRub`, `localTransportTotalRub`, `otherExpensesTotalRub`, `reserveTotalRub` на всю группу и поездку. При невозможности получить обязательную оценку задача сметы завершается ошибкой. C# добавляет цены выбранного проживания и посещений.
- Обязательные ключи присутствуют всегда. Для неизвестного nullable-значения передаётся `null`, для пустого списка — `[]`. Python нормализует пустой и пробельный текст во входных nullable-строках. Рабочая схема направления допускает `regionName: null`.
