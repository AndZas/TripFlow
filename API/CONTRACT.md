# Контракт C# backend ↔ Python API: скелет MVP

**Статус — черновик `v1` для проектирования интеграции.** Описаны согласованные структура и правила генерации и догенерации. Уточнения по nullable-полям, правила валидации, каталог ошибок и проценты бюджетного допуска будут согласованы отдельно. Примеры содержат условные значения.

## Общие соглашения

- Формат — JSON, имена полей — `camelCase`.
- MVP ориентирован на поездки по России; структура направления допускает другие страны.
- Денежные поля — целые рубли. `budgetRub` задаётся на всю группу и всю поездку, включая резерв.
- После приведения денежных значений к рублям положительная дробная сумма округляется вверх до целого рубля. Целые суммы сохраняются: `333` → `333`, `333.01` → `334`.
- Неизвестное значение — `null`. Нулевая цена означает подтверждённую бесплатность.
- Даты поездки — `YYYY-MM-DD`. Ночи проживания считаются как разница между `endDate` и `startDate`. Для питания и остальных ежедневных расходов обе даты учитываются включительно: от `2027-06-10` до `2027-06-15` — пять ночей и шесть полных дней расходов. Стоимость посещений учитывается по числу посещений.
- `taskId` создаёт backend до вызова Python и связывает со своей карточкой и её версией. Python возвращает тот же идентификатор.
- Необязательные сведения могут быть `null`.

### Обозначения типов

В столбце «Тип» используются значения ключа `type` из JSON Schema: `string`, `integer`, `number`, `object`, `array`, `boolean`, `null`. `integer` обозначает целое число, `number` — число, допускающее дробную часть. Запись `["string", "null"]` означает, что значением может быть строка или JSON-значение `null`.

Для объектов отдельно перечислены вложенные поля. Строка с `[]` описывает тип элемента массива, например `languageCodes[]`. Для строковых перечислений допустимые значения указаны в содержании. Даты и URL имеют тип `string`; их формат указан в содержании.

## Эндпойнты Python API

| Метод и путь | Назначение |
|---|---|
| `POST /v1/generate` | Полная генерация локации, вариантов отелей и достопримечательностей, оценок расходов |
| `POST /v1/generate-more` | Дополнительные варианты одного типа: отели или достопримечательности |

Оба запроса используют заголовки:

```http
Content-Type: application/json
X-API-Key: <ключ доступа к Python API>
```

| Заголовок | Тип | Содержание |
|---|---|---|
| `Content-Type` | `string` | Формат тела запроса: `application/json` |
| `X-API-Key` | `string` | Секретный ключ клиента для доступа к Python API |

## Запрос полной генерации

`POST /v1/generate`

```json
{
  "taskId": "task-001",
  "callbackUrl": "https://backend.example/internal/tripflow/results",
  "trip": {
    "destination": {
      "city": "Казань",
      "regionName": "Республика Татарстан",
      "countryCode": "RU",
      "coordinates": {
        "latitude": 55.796127,
        "longitude": 49.106405
      }
    },
    "startDate": "2027-06-10",
    "endDate": "2027-06-15",
    "travelers": 3,
    "budgetRub": 120000,
    "preferences": "Спокойная поездка, музеи, местная кухня, без хостелов"
  },
  "counts": {
    "hotels": 1,
    "attractions": 1
  }
}
```

| Поле | Тип | Содержание |
|---|---|---|
| `taskId` | `string` | Идентификатор задачи, созданный backend для сопоставления результата с карточкой |
| `callbackUrl` | `string` | URL обработчика backend, на который Python отправит конечный результат задачи |
| `trip` | `object` | Исходные параметры поездки для подбора вариантов и оценки расходов |
| `trip.destination` | `object` | Подготовленные географические данные выбранного направления |
| `trip.destination.city` | `string` | Название города назначения |
| `trip.destination.regionName` | `["string", "null"]` | Название региона для уточнения местоположения города |
| `trip.destination.countryCode` | `string` | Код страны назначения ISO 3166-1 alpha-2 |
| `trip.destination.coordinates` | `object` | Географические координаты города назначения |
| `trip.destination.coordinates.latitude` | `number` | Широта города в десятичных градусах |
| `trip.destination.coordinates.longitude` | `number` | Долгота города в десятичных градусах |
| `trip.startDate` | `string` | Дата начала поездки в формате `YYYY-MM-DD`; включается в расчёт ежедневных расходов |
| `trip.endDate` | `string` | Дата окончания поездки в формате `YYYY-MM-DD`; включается в ежедневные расходы, завершает период ночей проживания |
| `trip.travelers` | `integer` | Количество путешественников, для которых подбираются варианты и рассчитываются расходы |
| `trip.budgetRub` | `integer` | Целевой общий бюджет всей группы на всю поездку в рублях, включая резерв |
| `trip.preferences` | `string` | Свободный текст с пожеланиями пользователя к поездке |
| `counts` | `object` | Запрошенное количество вариантов каждого типа |
| `counts.hotels` | `integer` | Желаемое максимальное количество возвращаемых вариантов проживания |
| `counts.attractions` | `integer` | Желаемое максимальное количество возвращаемых достопримечательностей |

### Бюджет при полной генерации

| Условие | Поведение |
|---|---|
| Подбор укладывается в целевой бюджет | Возвращаются подходящие варианты и реалистичные оценки расходов |
| Подходящий вариант дешевле нижнего ориентира диапазона | Допускается к выдаче; нижний ориентир мягкий |
| Для подходящего подбора требуется превышение целевого бюджета | В первую очередь рассматриваются варианты в пределах согласованного верхнего допуска |
| Подходящий подбор превышает и верхний допуск | Возвращаются наиболее доступные подходящие варианты; само превышение не является ошибкой генерации |

Проценты бюджетного диапазона будут согласованы отдельно. Backend рассчитывает итог по выбору пользователя и оценкам расходов, показывает разницу с `trip.budgetRub`, включая превышение в пределах допуска. Цены альтернативных отелей не суммируются. Расходы и резерв не занижаются искусственно ради попадания в бюджет.

## Справочник поддерживаемых направлений

Общий файл `shared/data/destinations.json` расположен относительно корня репозитория TripFlow. Он содержит направления, доступные для выбора при создании карточки. Файл хранится в Git и используется командой как единый справочник названий, стран, регионов и координат городов.

Формат файла:

```json
{
  "destinations": [
    {
      "id": "ru-moscow",
      "city": "Москва",
      "regionName": "Москва",
      "countryCode": "RU",
      "countryName": "Россия",
      "coordinates": {
        "latitude": 55.75204,
        "longitude": 37.61781
      }
    }
  ]
}
```

| Поле | Тип | Содержание |
|---|---|---|
| `destinations` | `array` | Список направлений, доступных для выбора в TripFlow |
| `destinations[]` | `object` | Одна запись общего справочника направлений |
| `destinations[].id` | `string` | Уникальный стабильный внутренний идентификатор направления TripFlow |
| `destinations[].city` | `string` | Название города для отображения и поиска в интерфейсе |
| `destinations[].regionName` | `["string", "null"]` | Регион для уточнения направления и различения одноимённых городов |
| `destinations[].countryCode` | `string` | Код страны ISO 3166-1 alpha-2 для передачи в Python API |
| `destinations[].countryName` | `string` | Название страны для отображения рядом с городом |
| `destinations[].coordinates` | `object` | Географические координаты города для поиска и ссылки на карту |
| `destinations[].coordinates.latitude` | `number` | Широта города в десятичных градусах |
| `destinations[].coordinates.longitude` | `number` | Долгота города в десятичных градусах |

Названия, административная принадлежность и координаты подготавливаются по данным геокодирования или географического справочника и проверяются перед добавлением записи. Для включения направления проверяется возможность получить реальные варианты проживания, достопримечательности и денежные ориентиры, достаточные для оценки бюджета. Доступность и полнота конкретной выдачи определяются при выполнении запроса.

В начальном файле добавлена Москва; её координаты взяты из сохранённого ответа GeoNames в эксперименте `API/experiments/data-source-survey/`. Ответственный за интеграции Python готовит новые записи по результатам проверки источников; команда обновляет общий файл через Git. При добавлении страны используется та же структура записи.

Backend читает справочник и предоставляет его frontend для поиска и выбора города. Frontend показывает город, регион и страну; координаты могут использоваться для ссылки на карту. После выбора frontend передаёт backend идентификатор `id`. Backend находит соответствующую запись и формирует `trip.destination` из её полей `city`, `regionName`, `countryCode` и `coordinates`.

Python API получает готовый объект `trip.destination` и валидирует его. Справочник относится к интеграции TripFlow: самостоятельный клиент Python API может сформировать объект того же формата из своего справочника направлений.

## Запрос догенерации

`POST /v1/generate-more`

```json
{
  "taskId": "task-002",
  "callbackUrl": "https://backend.example/internal/tripflow/results",
  "target": "hotels",
  "trip": {
    "destination": {
      "city": "Казань",
      "regionName": "Республика Татарстан",
      "countryCode": "RU",
      "coordinates": {
        "latitude": 55.796127,
        "longitude": 49.106405
      }
    },
    "startDate": "2027-06-10",
    "endDate": "2027-06-15",
    "travelers": 3,
    "budgetRub": 120000,
    "preferences": "Спокойная поездка, музеи, местная кухня, без хостелов"
  },
  "count": 1,
  "optionBudgetRub": 60000,
  "refinement": null,
  "excluded": [
    {
      "name": "Отель А",
      "coordinates": {
        "latitude": 55.79,
        "longitude": 49.12
      }
    }
  ]
}
```

Общие поля `taskId`, `callbackUrl` и весь объект `trip` имеют ту же структуру, что в полной генерации.

| Поле | Тип | Содержание |
|---|---|---|
| `taskId` | `string` | Идентификатор отдельной задачи догенерации, созданный backend |
| `callbackUrl` | `string` | URL обработчика backend для конечного результата догенерации |
| `target` | `string` | Тип дополнительных вариантов: `hotels` или `attractions` |
| `trip` | `object` | Параметры поездки; все вложенные поля и их типы описаны в запросе полной генерации |
| `count` | `integer` | Желаемое максимальное количество новых альтернатив целевого типа |
| `optionBudgetRub` | `integer` | Предельная стоимость выбора одного нового варианта для всей группы в рублях |
| `refinement` | `["string", "null"]` | Дополнительное пожелание к новым вариантам; `null`, если уточнения нет |
| `excluded` | `array` | Исключённые варианты целевого типа; пустой массив означает отсутствие исключений |
| `excluded[]` | `object` | Данные одного объекта для сопоставления и исключения из выдачи |
| `excluded[].name` | `string` | Название объекта, который следует исключить |
| `excluded[].coordinates` | `object` | Географические координаты исключённого объекта |
| `excluded[].coordinates.latitude` | `number` | Широта исключённого объекта в десятичных градусах |
| `excluded[].coordinates.longitude` | `number` | Долгота исключённого объекта в десятичных градусах |

Для `hotels` поле `optionBudgetRub` относится к проживанию всей группы за всю поездку. Для `attractions` — к одному посещению всей группой. Backend вычисляет этот предел с учётом остальных расходов и резерва; стоимость заменяемого варианта в удерживаемые расходы не входит.

`excluded` объединяет уже использованные, показанные и отклонённые варианты, которые нельзя повторять.

### Правила догенерации

| Условие | Поведение |
|---|---|
| `target: "hotels"` | Возвращаются только новые варианты проживания |
| `target: "attractions"` | Возвращаются только новые достопримечательности |
| `refinement: null` | Используются предпочтения из `trip.preferences` |
| `refinement` содержит текст | Уточнение применяется вместе с `trip.preferences`; при противоречии пожеланий к целевому типу приоритет имеет уточнение |
| `excluded: []` | Исключения не применяются; ранее показанные объекты могут встретиться снова |
| `excluded` заполнен | Уверенно сопоставленные по названию и координатам объекты не возвращаются; неоднозначное совпадение не является основанием для исключения |

Backend передаёт актуальный контекст и итоговый текст уточнения в каждом запросе. `refinement` уточняет пожелания к целевому типу; направление, даты, число путешественников и бюджетные параметры определяются полями запроса. Выдача содержит уникальные варианты.

Для проверки `optionBudgetRub` используется собственная цена кандидата, а при её отсутствии — его рассчитанная оценка. Стоимость нового выбора для всей группы должна быть меньше либо равна лимиту. Для проживания учитывается вся поездка, для достопримечательности — одно посещение. Достопримечательность с обеими суммами `null` допускается как рекомендация с неизвестной стоимостью; её соответствие лимиту не подтверждено.

Для обоих эндпойнтов:

```http
202 Accepted

```

```json
{
  "taskId": "task-001",
  "status": "accepted"
}
```

| Поле | Тип | Содержание |
|---|---|---|
| `taskId` | `string` | Исходный идентификатор принятой задачи |
| `status` | `string` | Подтверждение приёма задачи: `accepted` |

Конечный результат поступает отдельным callback.

## Callback Python → backend

Python выполняет `POST` на `callbackUrl` из соответствующего запроса:

```http
Content-Type: application/json
X-Callback-Key: <callback key клиента>
```

| Заголовок | Тип | Содержание |
|---|---|---|
| `Content-Type` | `string` | Формат тела callback: `application/json` |
| `X-Callback-Key` | `string` | Отдельный секрет клиента для проверки отправителя callback |

При выдаче доступа к Python API клиент получает API key и задаёт отдельный случайно сгенерированный callback key. Клиент сообщает callback key Python-сервису при настройке доступа и сохраняет его на своей стороне. Python хранит соответствие API key и callback key каждого клиента; по ключу входящего запроса выбирает callback key для отправки результата.

Python передаёт callback key в заголовке `X-Callback-Key` при отправке результата на `callbackUrl`. Backend проверяет совпадение с сохранённым у него ключом до обработки тела callback. Ключи хранятся в environment или защищённом хранилище конфигурации; значения ключей передаются по HTTPS. Порядок регистрации клиента и выдачи доступа будет описан отдельно.

Backend подтверждает приём callback HTTP-ответом `200` или `204`.

Общая оболочка:

| Поле | Тип | Содержание |
|---|---|---|
| `taskId` | `string` | Исходный идентификатор задачи для сопоставления с запросом backend |
| `operation` | `string` | Выполненная операция: `generate` или `generate_more` |
| `status` | `string` | Итог задачи: `succeeded` или `failed` |
| `result` | `["object", "null"]` | Результат соответствующей операции при успехе; `null` при ошибке |
| `error` | `["object", "null"]` | Ошибка задачи по общей структуре ошибок; `null` при успехе |

### Успешная полная генерация

Поля внутри `result`:

| Поле | Тип | Содержание |
|---|---|---|
| `location` | `object` | Метаданные города назначения по структуре «Локация» |
| `hotels` | `object` | Выдача вариантов проживания и признак доступности продолжения поиска |
| `hotels.items` | `array` | Подобранные варианты проживания в пределах запрошенного количества |
| `hotels.items[]` | `object` | Один отель по общей структуре кандидата |
| `hotels.hasMore` | `["boolean", "null"]` | Наличие дополнительных вариантов проживания в текущем поиске |
| `attractions` | `object` | Выдача достопримечательностей и признак доступности продолжения поиска |
| `attractions.items` | `array` | Подобранные достопримечательности в пределах запрошенного количества |
| `attractions.items[]` | `object` | Одна достопримечательность по общей структуре кандидата |
| `attractions.hasMore` | `["boolean", "null"]` | Наличие дополнительных достопримечательностей в текущем поиске |
| `estimates` | `object` | Опорные денежные ставки и оценки расходов по структуре «Оценки расходов» |

#### Условия завершения полной генерации

Успешный результат требует определённого направления и пригодных оценок обязательных категорий расходов.

| Полученные данные | Итог callback |
|---|---|
| Метаданные направления и необходимые оценки бюджета сформированы, рекомендации найдены | `status: "succeeded"`; возвращаются найденные рекомендации и оценки |
| Найдено меньше рекомендаций, чем запрошено в `counts` | `status: "succeeded"`; возвращается фактическое количество без дополнения повторами |
| Рекомендации одного или обоих типов отсутствуют, необходимые оценки бюджета сформированы | `status: "succeeded"`; соответствующие `items` равны `[]`, остальные данные результата сохраняются |
| Дополнительные сведения, допускающие `null`, отсутствуют | `status: "succeeded"`; в соответствующих полях возвращается `null` |
| После предусмотренных попыток и резервных источников отсутствует пригодная основа для расчёта обязательной категории расходов | `status: "failed"`, `result: null`; причина передаётся в `error` |

Собственная цена кандидата возвращается в `price.amountRub`, его расчётная оценка — в `price.estimatedRub`. Общие опорные ставки возвращаются в `estimates` с их областью применимости. При пустом `items` получатель уведомляет об отсутствии конкретных рекомендаций и показывает доступную ориентировочную оценку. Сбой отдельного источника сам по себе не определяет итог задачи: учитывается достаточность полученных данных для бюджета. ### Успешная догенерация

Поля внутри `result`:

| Поле | Тип | Содержание |
|---|---|---|
| `target` | `string` | Тип возвращённых вариантов: `hotels` или `attractions` |
| `items` | `array` | Новые варианты выбранного типа с учётом исключений и уточнения |
| `items[]` | `object` | Один отель или одна достопримечательность по общей структуре кандидата |
| `hasMore` | `["boolean", "null"]` | Наличие дополнительных вариантов целевого типа в текущем поиске |

| Результат подбора | Итог callback |
|---|---|
| Найдены подходящие новые варианты | `succeeded`; возвращаются до `count` вариантов и `hasMore` по завершённости поиска |
| Поиск завершён, подходящих новых вариантов нет | `succeeded`, `items: []`, `hasMore: false` |
| Подбор не удалось выполнить, пригодной новой выдачи нет | `failed`, `result: null`; причина передаётся в `error` |

Догенерация возвращает альтернативы для выбора. Метаданные направления, общие оценки расходов и выбранные элементы карточки сохраняются. Backend применяет замену после выбора пользователя. При ошибке предыдущая выдача и её `hasMore` сохраняются; поля `items` и `hasMore` в ошибочном callback отсутствуют, поскольку `result` равен `null`.

### Локация

| Поле | Тип | Содержание |
|---|---|---|
| `city` | `string` | Название города назначения для отображения в карточке |
| `regionName` | `["string", "null"]` | Название региона, к которому относится город |
| `countryCode` | `string` | Код страны назначения ISO 3166-1 alpha-2 |
| `countryName` | `string` | Название страны назначения для отображения пользователю |
| `coordinates` | `object` | Географические координаты города назначения |
| `coordinates.latitude` | `number` | Широта города в десятичных градусах |
| `coordinates.longitude` | `number` | Долгота города в десятичных градусах |
| `timeZone` | `["object", "null"]` | Данные часового пояса города; `null`, если их не удалось определить |
| `timeZone.id` | `string` | Идентификатор часового пояса IANA, например `Europe/Moscow` |
| `timeZone.displayFromMoscow` | `string` | Готовая подпись смещения относительно Москвы на дату начала поездки |
| `countryCurrency` | `["string", "null"]` | Справочный код местной валюты ISO 4217 для отображения пользователю |
| `languageCodes` | `["array", "null"]` | Коды языков страны назначения для справочной информации |
| `languageCodes[]` | `string` | Один код языка из массива `languageCodes` |

Вложенные поля `timeZone` описывают значение объекта, когда `timeZone` отличается от `null`. Аналогично, `languageCodes[]` описывает элементы массива, когда `languageCodes` отличается от `null`.

При `null` в `regionName`, `timeZone`, `countryCurrency` или `languageCodes` соответствующие сведения не отображаются. Остальные данные локации используются независимо.

### Кандидат отеля / достопримечательности

| Поле | Тип | Содержание |
|---|---|---|
| `position` | `integer` | Порядок приоритета внутри текущей выдачи, начиная с `1`; меньшая позиция приоритетнее |
| `name` | `string` | Название реального отеля или достопримечательности |
| `coordinates` | `object` | Географические координаты конкретного объекта |
| `coordinates.latitude` | `number` | Широта объекта в десятичных градусах |
| `coordinates.longitude` | `number` | Долгота объекта в десятичных градусах |
| `address` | `["string", "null"]` | Адрес объекта для отображения в карточке варианта |
| `description` | `["string", "null"]` | Краткое описание объекта для знакомства с вариантом |
| `image` | `["string", "null"]` | URL подходящего изображения; `null`, если изображение отсутствует |
| `url` | `string` | URL объекта или источника либо поисковая ссылка, сформированная Python-сервисом |
| `price` | `object` | Собственная цена объекта и его расчётная оценка в рублях |
| `price.amountRub` | `["integer", "null"]` | Собственная цена объекта из источника; `null`, если пригодная цена неизвестна |
| `price.estimatedRub` | `["integer", "null"]` | Рассчитанная по подходящим справочным данным оценка стоимости кандидата; `null`, если обоснованная оценка недоступна |

Дополнительное поле отеля:

| Поле | Тип | Содержание |
|---|---|---|
| `stars` | `["integer", "null"]` | Звёздность `1`–`5` по данным источника; `null`, если числовая звёздность для отображения отсутствует |

Внешнее значение звёздности `0` отображается в контракте как `stars: null`. При `stars: null` интерфейс скрывает блок звёзд. Отель с неизвестной категорией допускается при наличии пригодной собственной цены. У каждого возвращаемого отеля заполнено хотя бы одно из полей `price.amountRub` и `price.estimatedRub`.

Дополнительное поле достопримечательности:

| Поле | Тип | Содержание |
|---|---|---|
| `category` | `["string", "null"]` | Категория объекта для отображения и подбора соответствующей справочной ставки; `null`, если категория неизвестна |

При наличии подходящей ставки для категории достопримечательности её расчётная стоимость возвращается в `price.estimatedRub`. Отсутствие категории или подходящих данных допускает `estimatedRub: null`.

Обе суммы отеля относятся к ориентировочной стоимости проживания одного путешественника за одну ночь. Обе суммы достопримечательности относятся к одному посещению одним человеком. В `estimatedRub` передаётся оценка для соответствующего кандидата; общие ставки поездки передаются в `estimates`.

Для `amountRub` используются данные, у которых известны валюта и единица стоимости и которые можно обоснованно привести к единицам контракта. Если это невозможно, возвращается `amountRub: null`; при наличии пригодных справочных данных используется `estimatedRub`.

| Состояние цены | Использование при проверке бюджета, расчёте и отображении |
|---|---|
| `amountRub` отличается от `null` | Используется `amountRub`, включая значение `0` |
| `amountRub: null`, `estimatedRub` отличается от `null` | Используется `estimatedRub`; пользователю обозначается расчётный характер суммы |
| У достопримечательности обе суммы `null` | Объект допускается как рекомендация с неизвестной стоимостью; при выборе его стоимость не включается в сумму, а итог обозначается как неполный |

Собственная цена из источника также является ориентиром и не гарантирует стоимость бронирования на даты поездки. Backend сохраняет возвращённую оценку вместе с кандидатом и использует её при его выборе.

`position` начинается с `1` в каждом ответе; при полной генерации порядок независим для отелей и достопримечательностей. Backend формирует общую очередь карточки с сохранением порядка внутри каждой выдачи.

Python подбирает изображение, пригодное для отображения по ссылке в интерфейсе сервиса, и возвращает его URL в `image`, например `"https://example.org/images/object.jpg"`. Если подходящего изображения нет, возвращается `null`.

При `image: null` интерфейс использует заглушку. При `address: null` или `description: null` соответствующие сведения не отображаются; остальные данные кандидата сохраняются. Кандидат должен иметь название и координаты реального объекта.

### Доступность дополнительных вариантов

`hasMore` определяется отдельно для каждого типа вариантов с учётом параметров подбора и исключений на момент поиска. Значение учитывает предусмотренные попытки получения данных и резервные источники.

| Значение | Значение для получателя | Действие получателя |
|---|---|---|
| `true` | Найден хотя бы один дополнительный подходящий уникальный кандидат сверх возвращённых | Допускается запрос дополнительных вариантов |
| `false` | Предусмотренный поиск завершён, дополнительных подходящих кандидатов нет | Полученные варианты остаются доступны. После их исчерпания или отклонения показывается отсутствие дополнительных вариантов; запрос догенерации с теми же параметрами подбора не отправляется |
| `null` | После предусмотренных попыток поиск остался неполным; наличие дополнительных кандидатов неизвестно | Полученные варианты остаются доступны. Пользователь может инициировать повторный поиск |

Количество возвращённых вариантов меньше запрошенного само по себе не определяет `hasMore`. Пустой `items` также допускает `false` или `null` в зависимости от завершённости поиска.

Повторный поиск при `hasMore: null` выполняется по действию пользователя через `POST /v1/generate-more`: передаются новый `taskId`, нужный `target`, актуальные параметры и исключения, включая уже показанные варианты. Текущая выдача и выбор пользователя сохраняются на время запроса. При `hasMore: false` новый поиск возможен после изменения параметров подбора.

### Оценки расходов

| Поле | Тип | Содержание |
|---|---|---|
| `accommodation` | `object` | Общая опорная ставка проживания для оценки бюджета поездки |
| `accommodation.perPersonPerNightRub` | `integer` | Опорная стоимость проживания одного человека за одну ночь в рублях |
| `accommodation.scope` | `string` | Территория исходного ориентира проживания: `city`, `region` или `country` |
| `admission` | `object` | Опорная ставка входного билета и предварительное число посещений |
| `admission.perVisitPerPersonRub` | `integer` | Опорная стоимость одного посещения одним человеком в рублях |
| `admission.suggestedVisitsPerPerson` | `integer` | Предварительное количество посещений на одного человека за всю поездку |
| `admission.scope` | `string` | Территория исходного ориентира стоимости посещения: `city`, `region` или `country` |
| `foodTotalRub` | `integer` | Ориентировочная сумма расходов на питание всей группы за всю поездку в рублях |
| `localTransportTotalRub` | `integer` | Ориентировочная сумма расходов на городской транспорт всей группы за всю поездку в рублях |
| `otherExpensesTotalRub` | `integer` | Ориентировочная сумма прочих планируемых расходов всей группы за всю поездку в рублях |
| `reserveTotalRub` | `integer` | Ориентировочная сумма резерва всей группы на всю поездку в рублях, включённая в общий бюджет |

`otherExpensesTotalRub` не дублирует проживание, питание, городской транспорт и входные билеты. Все значения `estimates` являются ориентировочными.

| `scope` | Смысл |
|---|---|
| `city` | Исходный ориентир относится к городу назначения |
| `region` | Использован региональный ориентир при отсутствии пригодного городского |
| `country` | Использован общестрановой ориентир как последний резерв при отсутствии пригодных городского и регионального |

`scope` соответствует фактической территории исходных данных. Пригодные ориентиры используются в порядке `city` → `region` → `country`.

Обязательные денежные оценки в `estimates` возвращаются целыми числами, без `null`. Если необходимую оценку получить невозможно, генерация завершается ошибкой. Отсутствие расчёта не подменяется нулём; нулевая сумма допустима только при обоснованном отсутствии затрат.

| Состояние выбора | Основа расчёта backend |
|---|---|
| Отель ещё не выбран, в том числе при отсутствии рекомендаций | `accommodation.perPersonPerNightRub` × число путешественников × число ночей |
| Отель выбран | Используемая сумма выбранного отеля из `price` × число путешественников × число ночей; заменяет предварительный расчёт проживания |
| Посещения ещё не выбраны, в том числе при отсутствии рекомендаций | `admission.perVisitPerPersonRub` × `admission.suggestedVisitsPerPerson` × число путешественников |
| Посещения выбраны | Сумма используемых цен выбранных посещений на всю группу; заменяет предварительный расчёт посещений |
| У выбранного посещения обе суммы `null` | Его стоимость не включается в итог; пользователю сообщается, что сумма не учитывает посещения с неизвестной стоимостью |

Неизвестная стоимость не обозначает бесплатность. Все итоги обозначаются как ориентировочные. При неполном итоге дополнительно выделяются выбранные посещения с неизвестной стоимостью и отсутствие их стоимости в сумме; соответствие всей поездки бюджету не подтверждается. Общая опорная оценка и заменивший её расчёт выбранных объектов одновременно не суммируются.

Итоговую сумму, сумму на участника и остаток/превышение бюджета вычисляет C# backend по этим данным и текущему выбору пользователя. К проживанию и посещениям добавляются `foodTotalRub`, `localTransportTotalRub`, `otherExpensesTotalRub` и `reserveTotalRub`.


## Структура ошибок

Объект ошибки общий для немедленного HTTP-ответа и callback:

| Поле | Тип | Содержание |
|---|---|---|
| `code` | `string` | Машинный код ошибки для выбора способа обработки на backend |
| `message` | `string` | Понятное описание причины ошибки |
| `fields` | `object` | Словарь сообщений по полям запроса; ключи — пути полей, например `trip.startDate`; может быть пустым |
| `fields.<путь поля>` | `string` | Сообщение об ошибке соответствующего поля запроса |

### Немедленная HTTP-ошибка

| Поле | Тип | Содержание |
|---|---|---|
| `taskId` | `["string", "null"]` | Идентификатор задачи; `null`, если его не удалось получить из запроса |
| `error` | `object` | Описание ошибки по общей структуре ошибок |

```json
{
  "taskId": "task-001",
  "error": {
    "code": "ERROR_CODE",
    "message": "Описание ошибки",
    "fields": {}
  }
}
```

В таком ответе `taskId` может быть `null`, если идентификатор не удалось получить из запроса. HTTP-статусы и полный каталог кодов будут определены отдельно. `ERROR_CODE` — обозначение места для кода в примере, не согласованный код ошибки.

### Ошибка в callback

```json
{
  "taskId": "task-002",
  "operation": "generate_more",
  "status": "failed",
  "result": null,
  "error": {
    "code": "ERROR_CODE",
    "message": "Описание ошибки",
    "fields": {}
  }
}
```
