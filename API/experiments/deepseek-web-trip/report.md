# Эксперименты TripFlow с DeepSeek

Дата фиксации результатов — 17 ноября 2026 года. Для Python API TripFlow выбрана облачная модель DeepSeek. В обоих стендах использовалась `deepseek-flash`. Схема поиска, источники цен и правила догенерации остаются открытыми решениями.

## Flash с поставщиками

[Стенд deepseek-flash](../deepseek-flash/README.md) перенёс сценарий карточки с LM Studio на DeepSeek и сохранил поиск в Russhotels и Geoapify, проверку условий по выдержкам и применение ставок Росстата. Модель обрабатывает свободный текст, проверяет условия по источникам и оценивает расходы. Python проверяет структуру ответа и рассчитывает суммы на группу.

| Проверка | Результат |
| --- | --- |
| Тесты Python | 49 из 49 |
| Разбор пожеланий | 10 из 10 контрольных карточек после уточнения промпта и проверки цитат |
| Проверка гостиничных условий по сохранённым выдержкам | 6 из 6 ожидаемых вердиктов |
| Дополнительные расходы | 24 из 24 проверок на шести карточках после уточнения промпта и учёта включений |
| Сквозная карточка | 2 отеля, 5 музеев, оценка дополнительных расходов 18 130 ₽ |

Сквозной подбор занял около 86 с, из которых около 81 с пришлось на поиск и проверку гостиничных условий. Запрос оценки дополнительных расходов после выбора занял около 2,9 с. Результаты относятся к контрольным сценариям этого стенда.

## Flash с веб-поиском

[Стенд deepseek-web-trip](README.md) отправляет модели всю карточку поездки, включая свободное направление, даты, размер группы, бюджет и пожелания. Flash параллельно ищет отели и достопримечательности в открытом вебе. Python загружает страницы из выдачи через DeepSeek Fetch, передаёт выдержки в отдельный запрос за JSON и проверяет цитаты. Фото ищется на страницах объектов и в Wikimedia Commons. Варианты выдаются со ссылками на источники.

Карточка показывает найденный тариф с валютой и единицей. Опубликованная ставка за ночь используется как ориентир, а предложение на всю группу требует подтверждённых дат и числа гостей. Бюджет суммирует найденные цены и оценки на питание, городской транспорт, прочие расходы и резерв. Ориентир по цене за номер рассчитывается с допущением двух человек на номер. Иностранные цены пересчитываются по курсу Банка России. При неизвестной цене учтённая сумма помечается как неполная.

| Прогон | Результат |
| --- | --- |
| Санкт-Петербург, браузерный сценарий | 3 отеля и 2 музея. После выбора отеля и одного музея стенд оценил поездку в 38 554 ₽. |
| Стамбул | 3 отеля и 2 достопримечательности. При расчёте использовались найденные цены в рублях, евро и турецких лирах. Итог по выбранным вариантам — 52 896 ₽. |
| Фото и карта | В Edge загрузилось фото Русского музея из Wikimedia Commons. Карты открываются по координатам, а при их отсутствии по названию и адресу. Покрытие фотографиями и точными координатами пока частичное. |
| Пользовательские поиски в Китае и Японии | При бюджете около 500 000 ₽ на четверых на неделю и пожелании хорошего отеля нашлись подходящие варианты, но без цен на отели. У части карточек также не хватало адресов, фотографий и других сведений. |

Подбор в технических прогонах занимал около одной-двух минут. Автор проекта в своих прогонах отметил более подходящие рекомендации и более быстрый поиск по сравнению с прежним подходом. Сопоставимый замер на одинаковом наборе карточек пока не проводился. Открытый веб-поиск расширил географию и позволил передавать модели предпочтения свободным текстом. Главный пробел — покрытие ценами и наличием номеров на конкретные даты и состав группы.

## Фактические расходы

По наблюдению автора проекта в кабинете DeepSeek, один веб-подбор с неполными данными стоил **около 13 ₽**. Это отдельное наблюдение по одному подбору. Доли приведены так, как их показал кабинет, с округлением.

| Статья в кабинете | Доля |
| --- | ---: |
| Токены DeepSeek Flash | 34% |
| Поиск | 43% |
| Tool Fetch | 14% |
| Server Tool Fetch | 8% |

Оценка автора до **50 ₽** за более полный подбор с догенерацией — прогноз. Стоимость такого сценария отдельно не измерялась. В измеренном запуске поиск и загрузка страниц вместе дали около двух третей расходов, поэтому экономию нужно проверять как на уровне числа обращений к вебу, так и на уровне токенов.

## Что проверить перед интеграцией

1. На одном наборе поездок сравнить автономный поиск DeepSeek с управляемым поиском из Python. В обоих режимах оставить Flash задачи интерпретации пожеланий, оценки соответствия вариантов и бюджета. Снять цену и время на карточку и долю отелей с тарифом для конкретных дат и группы. Отдельно посчитать покрытие адресами, фото и координатами.
2. Проверить выборочную загрузку страниц по качеству выдачи, удаление дубликатов и повторное использование найденных сведений при догенерации. Сравнить отдельную загрузку страниц через Python и через DeepSeek Fetch на тех же источниках.
3. Проверить независимые источники тарифов и наличия номеров, в том числе страницы бронирования. Отдельно оценить, какие пожелания помогают подобрать варианты, какие требуют подтверждения, и какие можно оставить в свободной форме в пользовательском сценарии.
