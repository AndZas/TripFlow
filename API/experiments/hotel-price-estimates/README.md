# Hotel price estimates

**Эксперимент завершён 28.10.2026. Рассмотренные кандидаты не приняты для текущего MVP TripFlow.** Makcorps предоставляет ограниченный тестовый пакет с последующим платным использованием; Skyscanner требует партнёрского одобрения и оказался недоступен для текущего студенческого прототипа. Dataestur не принят как замена: региональное покрытие Испании, доступ и права конкретного набора не подтверждены. Это решения о пригодности источников при текущих ограничениях проекта, а не результаты живого сравнения цен.

Живые запросы цен **не выполнялись**. Программа live-тестов из TASK прекращена по решению владельца. Ключи для завершения эксперимента получать не требуется; способ оценки проживания будет обсуждаться отдельно. Код стенда сохранён как исследовательский артефакт: Python 3.10+, стандартная библиотека, реальные HTTP-адаптеры без проверки на живых ответах. [Исходное задание](TASK.md), [официальные источники](reports/sources.md), [итоговая оценка](reports/assessment.md).

В репозиторий входят задание, этот README, Python-код и локальные тесты, config.example.json, .env.example, .gitignore и два итоговых документа reports. Локальные ключи, config.local.json, кэш Python и runs исключены из Git. Контракт и код приложения не изменялись.

## Подготовка и проверка

```powershell
cd F:\Files\PythonProjects\TripFlow\API\experiments\hotel-price-estimates
python -m unittest -v test_hotel_price.py
python .\hotel_price_test.py --init-config
python .\hotel_price_test.py --offline
```

`--init-config` создаёт игнорируемый Git файл `config.local.json`, не перезаписывая существующий. Он заполняет **синтетические исследовательские даты**: заезд через 30 дней на две ночи, городской диапазон на месяц, Dataestur за прошлый месяц. Все провайдеры выключены. Это тестовые параметры, не параметры пользователя TripFlow. Даты можно заменить; просроченные/слишком широкие диапазоны блокируются перед HTTP.

`--offline` никогда не делает HTTP, даже при установленных ключах и включённых провайдерах. Проверяет конфигурацию, читает существующие Geoapify samples и сохраняет отчёт. Свежий шаблон без локального config тоже можно проверить. `.env` автоматически не читается, зависимости устанавливать не требуется.

## Справка для возможного возобновления

Следующие инструкции сохранены для воспроизводимости стенда. Они не являются текущим планом подключения источников: эксперимент закрыт, все источники по умолчанию выключены. Возобновление потребует новой проверки условий и отдельного решения владельца.

### Makcorps

1. Самостоятельно откройте [официальную регистрацию](https://api.makcorps.com/register), создайте аккаунт. Страница заявляет **15 free credits, без карты**; главная страница показывает 30. Реальный остаток смотрите в своём кабинете, 30 не считать гарантией. Карту и платный план не подключайте.
2. Скопируйте свой personal API key из кабинета в переменную **`MAKCORPS_API_KEY`**. Расположение поля в авторизованном кабинете нами не проверялось; публичная [документация](https://www.makcorps.com/documentation/getting-started/) называет его API key.
3. Посмотрите тип бесплатного аккаунта, остаток и стоимость `/account`, `/mapping`, `/hotel`, `/city`. Для стенда необходимо подтверждение, что `/account` **не тратит credit**, выбранные вызовы расходуют только бесплатный остаток и не создают оплаты. Одна гостиничная операция сопровождается проверкой остатка до и после: всего 3 HTTP. Нет подтверждения бесплатности `/account` — live блокируется.
4. Уточните право сохранить небольшие ответы для учебного исследования и показывать цены в TripFlow. [Общие условия](https://www.makcorps.com/terms/) не дают ясного разрешения на такой показ API-данных. Наличие ключа не заменяет эти условия.
5. Старый [бесплатный endpoint](https://docs.hotelapi.co/free-hotel-api) использует **отдельный JWT**, а не документированный современный `api_key`. Он даёт случайные будущие даты, до 30 отелей, без выбора гостей. **Не вставляйте API key в `MAKCORPS_FREE_JWT`.** Этот сценарий доступен только если поставщик подтвердит действующий JWT-доступ и выдаст соответствующий токен. Пароли стенд не принимает и JWT сам не получает. Без этого сценарий free пропускается; mapping/hotel можно исследовать отдельно в подтверждённом бесплатном пакете.

При обращении к поддержке можно спросить самостоятельно: «Can my no-card free account call /account without consuming credits? What are the credit costs of /mapping, /hotel and /city? Is the legacy /free/{city} JWT API still available? May a non-commercial student project store small samples and display indicative prices with attribution and a source link, without booking?» Стенд не отправляет это сообщение.

### Skyscanner

1. Откройте [Authentication → Request Skyscanner API key](https://developers.skyscanner.net/docs/getting-started/authentication). Требуется заявка в Partnerships и одобрение; автоматическая выдача ключа не обещана. Заявку подаёт владелец проекта.
2. Честно опишите учебный TripFlow, отсутствие бронирования и потребность в **Stays Indicative Prices**, **Stays Autosuggest**, **Culture API**. Уточните бесплатность выбранного объёма, отсутствие биллинга, право хранить исследовательские примеры и показывать агрегированную цену без бронирования.
3. После одобрения сохраните выданный ключ в **`SKYSCANNER_API_KEY`**. Если доступ или price-only use не разрешены, этот кандидат остаётся `not_tested`; получать платный доступ для эксперимента не требуется.

[FAQ о Flights](https://developers.skyscanner.net/docs/faqs) ограничивает использование цен без переходов к бронированию. Это не доказательство идентичных условий Stays: согласовать следует именно ваш сценарий Stays. Перед запуском Culture проверит RUB, locale и market. Если RUB отсутствует, запуск остановится; можно отдельно выбрать подтверждённую валюту, сохранив исходную сумму. Непроверенные курсы не подставляются, `amount_rub` останется `null`.

### Dataestur

Пока не запрашивайте ключ специально для этого эксперимента. [Публичный OpenAPI](https://www.dataestur.es/app/themes/mini-mandrake/apidata/openapi.json) объявляет subscription key (`Ocp-Apim-Subscription-Key`), но публичный порядок его самостоятельного получения не найден. Если SEGITTUR предоставит официальный ключ и подтвердит условия выбранного набора, используйте **`DATAESTUR_API_KEY`**. Это региональный CSV-бенчмарк по Madrid/Barcelona, не цена выбранного отеля. Первое чтение сохраняет только названия столбцов и число строк; денежные колонки и единицы нужно установить по метаданным до их нормализации.

## Переменные среды Windows

Откройте **«Изменение переменных среды текущего пользователя» → «Переменные среды» → верхний список пользовательских переменных → «Создать»**. Добавьте имя `MAKCORPS_API_KEY` и полученный ключ как значение. `SKYSCANNER_API_KEY` добавляйте после его выдачи. Секреты не отправляйте в чат и не записывайте в config.

Перезапустите Codex, чтобы новый процесс получил переменные. Если переменные уже сохранены на уровне пользователя Windows, текущий PowerShell может загрузить их без печати значений:

```powershell
$env:MAKCORPS_API_KEY = [Environment]::GetEnvironmentVariable('MAKCORPS_API_KEY', 'User')
$env:SKYSCANNER_API_KEY = [Environment]::GetEnvironmentVariable('SKYSCANNER_API_KEY', 'User')
python .\hotel_price_test.py --offline
```

Значения, установленные только через `$env:...` в другом окне PowerShell, Codex не унаследует. Достаточно сообщить, какие имена переменных добавлены и что подтверждено в кабинете/условиях, без значений ключей.

## Включение live

В `config.local.json` выставляются только проверенные факты. `enabled=true` выбирает источник. `review.free_no_billing=true` вместе с `cost_evidence` подтверждает безопасную стоимость. `research_storage_allowed=true` вместе с `terms_evidence` разрешает сохранение очищенных наблюдений. Поля evidence — ссылка/описание условий или подтверждения поставщика, без ключей и персональных данных. Для Skyscanner дополнительно требуются `access_approved` и `price_only_display_allowed`. Makcorps может исследоваться приватно при разрешённом хранении, но до подтверждения показа решение будет `not_tested` с `access_or_display_rights_unclear` для применения в MVP.

У Makcorps отдельно установите `account_check_free`, `account_cost_evidence` и подтверждённую стоимость используемых сценариев в `credit_costs`. Значение `null` блокирует этот сценарий. Нельзя подставлять предполагаемую стоимость. `--credit-budget` ограничивает суммарный расход; он должен быть **строго меньше** проверенного остатка, минимум один credit остаётся. При расхождении ожидаемого и фактического расхода работа прекращается. Ошибочный запрос тоже учитывается как потенциально списанный, повторов нет.

```powershell
python .\hotel_price_test.py --live --providers makcorps --max-requests 12 --credit-budget 3
python .\hotel_price_test.py --live --providers skyscanner --max-requests 10
```

Максимум 24 HTTP за запуск, 14 credits бюджета, 2 hotel-specific сценария. По умолчанию 12 HTTP/3 credits. Каждый Makcorps сценарий требует места для pre-check, запроса и post-check; при нехватке не начинается. Не запускать два процесса одновременно на одном аккаунте: остаток между запросами может измениться внешним клиентом.

Сценарии Makcorps: `free`, `mapping`, `hotel`, `city`. По умолчанию free → mapping одного существующего парижского примера → hotel только при точном имени и географии → несуществующее название. Free можно исключить, если JWT недоступен. Для city сначала добавьте mapping города (`name: "Paris", city: "Paris"`), затем city с `mapping_name: "Paris"`; либо укажите официальный ID с `id_evidence`. Нельзя придумывать ID. Города: Paris, Moscow, Istanbul, Suzdal, Madrid, Barcelona и явно вымышленное контрольное название. Это набор для последовательных малых исследований.

Skyscanner сначала делает 3 Culture-запроса, потом Autosuggest и максимум один indicative search на город. Шаблон: Paris, Madrid, несуществующий город — максимум 9 HTTP. Entity ID выбирается только при единственном совпадении имени и близости координат. `grouping: aggregated/by_date/by_month` управляет группировкой. `filter` поддерживает документированные stars/accommodation/chain/group поля; конкретные enum необходимо подтвердить и указать `filter_evidence`. Отдельный запуск можно настроить на даты карточки. Для daily/monthly группировки непрочитанный составной ключ не превращается в придуманную дату.

`verified_price_basis` позволяет записать только **подтверждённую** единицу: для Makcorps объект по имени сценария (`hotel`, `city`, `free`) с `period: per_night/per_stay`, `occupancy_basis: per_room/per_person`, `evidence`; для Skyscanner — `occupancy_basis` и `evidence`. Если документация не устанавливает единицу, оставить пустым: число попадёт в наблюдения, но не в пригодный бюджет/RUB. Не делить цену на путешественников.

## Выходные данные и границы проверки

Каждый запуск пишет `reports/runs/<UTC-id>/results.json`, `live-results.md`, `samples/`. В JSON: все HTTP статусы/задержки, сценарии, квоты до/после, очищенные наблюдения, единицы и доли пригодности по областям hotel/city/region. Исходные payload, query string с ключами, заголовки и тела ошибок не сохраняются. Samples содержат до двух нормализованных наблюдений на разрешённый источник. URL ограничены фиксированным списком, redirect запрещён. При любой HTTP/сетевой ошибке источник останавливается, в том числе при 401/403/429; автоматических повторов нет. Sandbox-only разрешение блокируется перед запросами.

Код выхода: `0` — offline или завершённые настроенные live-сценарии, `2` — неверная конфигурация, `3` — live пропущен/неполон. `completed` означает выполненный план запросов; только метрики наблюдений показывают пригодность цены. Пустой HTTP 200 не означает найденную цену. Общая оценка в reports/assessment.md обновляется после проверки валидного live-run; пропущенный запуск автоматически туда не продвигается.

Тесты используют подставной HTTP-транспорт. Они проверяют ограничения, безопасность, matching и нормализацию, но не доказывают доступность реальных аккаунтов или актуальную схему живого ответа. После добавления ключей необходим малый первый live-run.
