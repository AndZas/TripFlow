# Результаты дополнительных проверок TripFlow

**15.10.2026, Москва.** Проверки выполнены под Python 3.14 с уже настроенными локальными Geoapify Free и GeoNames. Ключи не выводились, аккаунты/подписки/бронирования не создавались. Новых API-ключей для этого этапа не требуется.

## Практический вывод

**Geoapify можно брать основным кандидатом для каталога мест и жилья; GeoNames — для справочных данных города/страны.** Это подтверждено небольшими выборками четырёх городов. Фотографии, описания, рейтинги и реальные гостиничные тарифы эти результаты полноценно не закрывают. OpenTripMap пока необязателен: его стоит исследовать отдельно именно как возможное дополнение контента, без обещания полного покрытия.

Есть важное уточнение к будущей модели идентификаторов: Geoapify Search и Details могут возвращать разные `place_id` для одного исходного объекта. В эксперимент добавлено сопоставление по OSM type/id и устойчивое локальное исключение такого объекта при отклонении. Нужно сохранить и идентификатор источника, и Geoapify lookup ID; не считать непрозрачную строку поставщика вечным идентификатором приложения.

## Проверки сценариев

- **Кириллица:** `Москва` разрешилась в нужный населённый пункт у обоих геокодеров. Русское отображаемое имя поддерживается.
- **Неоднозначность:** `Springfield` вернул несколько кандидатов; фильтр US ограничил страну, но не отменил необходимость выбора конкретного города.
- **Пустой поиск:** искусственные названия города и музея дали корректные пустые списки с HTTP 200. Это отдельное состояние, не ошибка формирования карточки.
- **Предпочтение:** vegetarian-фильтр ресторана принят; возвращённые данные позволили проверить признак. Это не доказательство поддержки произвольного свободного текста предпочтений.
- **Отклонения:** локальное исключение по идентификатору действует только в переданном контексте карточки; другая карточка сохраняет кандидата. Исчерпание маленькой выборки возвращает пустой список без бесконечного повторного поиска.
- **Идентичность Details:** одинаковые OSM type/id при разных lookup ID подтверждены у отеля и ресторана. Пара source type/id теперь сохраняется в примерах, а opaque ID остаётся доступен для запросов.

Диапазоны задержек полного прогона: Open-Meteo **0.424–0.547 с**, GeoNames **0.381–1.353 с**, Geoapify **0.519–1.201 с**. В точечном повторе Details до 1.249 с. Это один последовательный прогон; p95, устойчивость под нагрузкой и SLA не измерялись.

## Расчёт проживания по базовой цене

Реализован отдельный **локальный калькулятор**, который не обращается к API и не подставляет цену. Он принимает базовую цену **одного номера за ночь**, вместимость этого типа номера, гостей, ночи, валюту, источник/дату и статус налогов. Число номеров округляется вверх, деньги считаются через Decimal. Выход явно помечен как оценка, availability остаётся null.

Это позволяет проверить предложенный пользователем подход арифметически. Он **не решает получение базовой цены и вместимости** из внешнего источника. Если источник не найден, поле остаётся неизвестным. Историческая цена, опубликованный тариф и ручное предположение записываются как разные основания; средняя цена не генерируется из воздуха. Формула предполагает одинаковые номера и отсутствие дополнительных ограничений расселения/детских тарифов.

Пошаговое заполнение локального JSON и запуск калькулятора — в [EXTENDED.md](../EXTENDED.md). В шаблоне цена не заполнена, поэтому случайного расчёта по вымышленной сумме не будет. Рыночные цены в автоматических тестах не используются, только подписанные искусственные значения.

## Что дальше от пользователя

1. Для повторения API-тестов **дополнительных действий и ключей не нужно**: запустить `run_extended.py`. Полная инструкция — [здесь](../EXTENDED.md).
2. Если нужен пример оценки реального отеля: выбрать конкретный тип номера, вручную найти допустимый публичный тариф/основание и вместимость либо явно оформить ручное допущение; заполнить локальный шаблон. Ключи и личные данные в него не добавлять.
3. С командой согласовать, какие поля обязательны в карточке. Сейчас основное препятствие — полнота контента и цены, а не подключение Geoapify/GeoNames.
4. OpenTripMap имеет смысл включать в следующий отдельный эксперимент ради описаний/изображений, если они обязательны. Получать его ключ просто для повторения нынешних проверок не требуется.

По результатам можно двигаться к обсуждению контракта Python API, явно разделяя каталог объекта, оценку бюджета и подтверждённое предложение на даты. Эти продуктовые решения ещё не утверждены командой.
