# TripFlow: сводка данных внешних API

Сводка эксперимента от 15 октября 2026 года. «Заполненность» означает долю непустых значений в нашей небольшой выборке, а не гарантию поставщика. Для Geoapify знаменатель — 100 объектов из Парижа, Москвы, Стамбула и Суздаля (по 5 объектов каждой из 5 категорий на город, радиус 3 км). Категории могут пересекаться. Для малых справочных ответов приведены фактически увиденные значения без статистических обещаний.

## API, проверенные живыми запросами

### Geoapify Places — главный кандидат на POI и справочник объектов размещения

**Endpoint:** `GET https://api.geoapify.com/v2/places` (Places API v2). API key обязателен. В нашем плане Free запрос Places до 20 результатов расходует 1 кредит.

**Параметры и фильтры, проверенные в эксперименте:** `categories` — категория или список категорий; `filter=circle:долгота,широта,радиус_в_метрах`; `limit` (в опыте 5, также поддержан максимум 20); `lang`. Категории: музеи `entertainment.museum`, исторические/туристические места `tourism.sights`, природа `natural`, рестораны `catering.restaurant`, размещение `accommodation.hotel`. Также проверен дополнительный фильтр `vegetarian=yes` для ресторанов. Координаты города сначала получали геокодером.

**Возвращаемые полезные поля и заполненность:**

| Поле | Непусто | Что это значит |
|---|---:|---|
| Название | 91/100 (91%) | У части природных объектов отсутствовало |
| Строка `formatted` | 100/100 (100%) | Это не всегда полный почтовый адрес |
| Координаты | 100/100 | Пригодны для карты и расстояний |
| Идентификатор поставщика | 100/100 | `place_id`; может отличаться между Places и Details |
| OSM type/id источника | Имеются у объектов, где поставщик их отдаёт | Сохранять вместе с `place_id`; устойчивый ключ источника для найденных объектов |
| Сайт | 27/100 (27%) | Не рассчитывать на ссылку для каждого места |
| Прямая ссылка на фото | 3/100 (3%) | Слишком редко для обязательной фотографии |
| Описание | 3/100 (3%) | Не использовать как обязательное поле |
| Часы работы | 14/100 (14%) | Не подтверждают расписание на даты поездки |
| Кухня, рестораны | 9/20 (45%) | Есть только у части кафе и ресторанов |
| Отзывы/числовой рейтинг | 0/100 (0%) | В этой выдаче рейтинга не было |
| Числовая цена | 0/100 (0%) | `fee`/платность не равны цене |
| Наличие номера на даты | 0/100 (0%) | Places — не поиск гостиничных тарифов |
| Категории, страна | Проверены на выдаче | Подходят для отбора и валидации категории/города |

**Details:** `GET https://api.geoapify.com/v2/place-details` с `id=<place_id>` и `features=details`. Проверены 2 живых запроса в основном прогоне и повторные детали в последующем точечном тесте. Детали не добавили цены или доступность. По одному объекту 2/2 сохранили связь с тем же OSM объектом, хотя `place_id` изменился. Для отклонений в карточке не полагаться только на этот непрозрачный ID.

**Вывод:** лучший проверенный единый запрос для каталога музеев, достопримечательностей, природы, ресторанов и справочных отелей. Это минимизирует число поставщиков, но не закрывает фото, рейтинг, описание, тариф и наличие.

### GeoNames — резервный/справочный геокодер

**Endpoints:** `GET https://secure.geonames.org/searchJSON`, `countryInfoJSON`, `timezoneJSON`. Используется личный активированный username; API key не нужен. В опыте `searchJSON` вызывался с `name_equals`, `maxRows=10`, `featureClass=P`, `style=FULL`, `lang=en`, опциональным `country`. На проверку неоднозначного названия нужно показывать варианты, а не автоматически брать первый.

**Возвращаемые поля:** географический `geonameId`, имя/альтернативные имена, страна и её ISO-код, административная область, населённый пункт/тип объекта, широта/долгота, население; `countryInfoJSON` даёт справочный код валюты страны; `timezoneJSON` — имя зоны IANA и смещение для переданных координат. Четыре города (Париж, Москва, Стамбул, Суздаль) подтвердились; также проверены кириллица, фильтр страны, неоднозначный Springfield и корректный пустой результат. Проценты заполненности не рассчитывались на четырёх городах.

**Вывод:** держать как источник/резерв для разрешения города и метаданных страны. Не вызывать повторно `countryInfo` для каждого кандидата одной страны: один запрос на уникальный код страны достаточно. Он не заменяет каталог мест или гостиничные цены.

### Open-Meteo Geocoding — рабочая альтернатива GeoNames для поиска города

**Endpoint:** `GET https://geocoding-api.open-meteo.com/v1/search`; проверялись `name`, `count=10`, `language`, опциональный `countryCode`. Бесплатный hosted-сервис имеет некоммерческие условия.

**Возвращаемые поля:** `id`, `name`, `latitude`, `longitude`, `country`, `country_code`, `admin1`, `population`, `timezone`, `feature_code` и близкие географические атрибуты. Работали четыре города, кириллица и фильтр страны; неоднозначный Springfield вернул несколько кандидатов, несуществующий город — пустой ответ. Заполнение по полям не оценивалось как статистика.

**Вывод:** можно выбрать вместо GeoNames для простого поиска города и координат; одновременные вызовы обоих геокодеров для каждого поиска обычно избыточны. Совпадение их ID в тесте не независимая проверка: источники данных связаны.

### Frankfurter v2 — курсы валют

**Проверенный endpoint:** `GET https://api.frankfurter.dev/v2/rate/EUR/RUB`. Получен курс EUR/RUB с датой (пример прогона: 14.10.2026, 93.98). Поля ответа: дата курса, базовая валюта, котируемая валюта, числовой курс. Это дневной справочный курс, не цена покупки и не курс оплаты конкретной гостиницы. Вызов v1 для EUR/RUB вернул 404; использовать для реализации проверенный v2.

**Фильтры:** код базовой и целевой валюты в пути endpoint; в API предусмотрены выбор даты/диапазона согласно документации. В эксперименте проверен актуальный ответ v2, а не точность широкого набора исторических дат.

**Вывод:** обращаться только при необходимости пересчитать сумму между валютами; не запрашивать курс на каждый POI или при каждом показе неизменённой карточки.

### Unicode CLDR — справочник валют страны

**Источник:** официальный JSON CLDR currency data. В эксперименте получена валюта для FR — EUR; расширенные проверки GeoNames дали справочные коды FR/EUR, RU/RUB, TR/TRY.

**Поля/фильтр:** код территории страны выбирает данные; результат — стандартные коды валют, доли/разряды и периоды применимости. Заполненность не выражается процентом: это справочник, а не поиск объектов. Валюта страны не гарантирует, что все гостиничные предложения выставлены именно в ней.

**Вывод:** загружать/обновлять справочник как локальные данные и применять без отдельного сетевого запроса на пользовательский поиск. Зафиксировать версию релиза.

### OpenStreetMap через публичный Overpass — запасной источник объектов

**Endpoint:** `POST https://overpass-api.de/api/interpreter`; запрос по координатам и радиусу с OSM тегами. Проверялись категории музеев, historic, nature, restaurants и hotels. Ответ содержит OSM `type/id`, координаты (у ways/relations — центр), теги вроде `name`, `amenity`, `tourism`, `opening_hours`, адресные/контактные теги, если они внесены участниками.

**Результат:** в ранних небольших прогонах часть выдач была HTTP 200 и содержала объекты, но были повторяющиеся таймауты и ошибки 5xx. Процент заполненности по общей выборке не вычислялся. Публичный Overpass не имеет SLA и требует соблюдать нагрузочные правила; для OSM нужна атрибуция и соблюдение ODbL.

**Вывод:** годится для эксперимента или аварийного резервного пути с ограничением запросов; не делать публичный общий Overpass обязательной зависимостью основного сценария. Geoapify использует данные OSM, поэтому два источника не всегда дают независимое покрытие.

### SIX ISO 4217 — официальный список кодов валют

**Что запрашивали:** официальный XML List One. Запрос не прошёл проверку TLS-сертификата в окружении Python; валидные поля ответа и заполненность не измерены. Это сбой соединения в нашей среде, а не доказательство неисправности API.

**Вывод:** допустимый справочный источник для отдельной повторной проверки сертификата/загрузки; для первого прототипа CLDR уже даёт локальный справочник валют.

## Минимальная схема запросов для прототипа

1. При вводе направления вызвать **один** геокодер (GeoNames или Open-Meteo), показать варианты при неоднозначности и сохранить выбранные ID, координаты, страну и часовой пояс.
2. Валюту территории брать из локального **CLDR**; `country.currency` держать отдельно от валюты конкретного предложения.
3. Получать места одним поставщиком — **Geoapify**: запрашивать только выбранные пользователем типы объектов, только нужный радиус и небольшой `limit`; расширять выборку отдельным запросом лишь когда пользователь просит ещё варианты. На первом экране обычно не нужны все пять категорий сразу.
4. **Details** вызывать только для выбранных/открытых кандидатов и только если реально нужны дополнительные поля. Хранить собственный ID, Geoapify `place_id` и при наличии OSM type/id; исключения делать в контексте конкретной карточки.
5. Курсы **Frankfurter v2** запрашивать только если валюта бюджета отличается от валюты отображаемой цены; переиспользовать курс на дату ответа.
6. Отели из Geoapify считать только каталогом. Реальную цену и доступность получать отдельным Booking/Expedia API после решения по партнёрству. Пока такого доступа нет, показывать базовую цену только как отдельную явно подписанную оценку с источником и датой; если основание отсутствует — не подставлять вымышленную цену.

**Практический выбор:** Geoapify + один геокодер + CLDR закрывают поиск места и базовые метаданные с минимумом поставщиков. Frankfurter добавляется условно. GeoNames может заменить Open-Meteo как второй источник/резерв; Overpass остаётся резервом с оговоркой по устойчивости. Ни одна из проверенных бесплатных POI-выдач не дала цену или наличие гостиницы.
