# Дополнительные проверки: как запустить и что они доказывают

Этот сценарий добавлен после успешных локальных запусков Geoapify и GeoNames. Он использует тот же `.env`, Python 3.14 и отдельное окружение эксперимента. **Новых ключей не нужно. OpenTripMap остаётся необязательным.**

## Самый простой запуск в PyCharm

1. Откройте **`run_extended.py`** в папке `API/experiments/data-source-survey`.
2. Выберите существующий интерпретатор `.venv\Scripts\python.exe` из этой папки.
3. Нажмите **Run**. Параметры можно оставить пустыми. Скрипт сам прочитает `.env`.
4. В конце откройте файл **`assessment.md`** по пути, который напечатает консоль. Это читаемая сводка с `pass / warn / fail / skipped`, а не только технические логи.
5. Для конкретного запроса откройте соседний `live-results.md`, для машинной проверки — `checks.json` и `results.json`.

Если копируете старую конфигурацию запуска, удалите `--no-keys`, `--offline` и старые параметры `--providers`: иначе часть проверок сознательно пропустится. Файл `.env` не нужно переименовывать и не нужно присылать в чат. `GEOAPIFY_FREE_PLAN=1` включайте только для своего Free с доступной квотой; доступ не переключается автоматически на платный.

В PowerShell из этой папки:

```powershell
.\.venv\Scripts\python.exe run_extended.py
```

## Что проверяется

| Сценарий | Проверка |
|---|---|
| Париж, Москва, Стамбул, Суздаль | Страна, населённый пункт, координаты и IANA identifier; сравнение GeoNames ID у двух геокодеров |
| Справочные данные FR/RU/TR | EUR/RUB/TRY в CountryInfo; валюта страны отделена от валюты конкретной цены |
| По пять категорий в каждом городе | Музеи, история/культура, природа, рестораны/кафе, жильё; до пяти результатов на запрос |
| Качество каждой выборки | ID, координаты, соответствие категории, заполненность адреса/сайта/фото/описания/кухни/часов/цен |
| Кириллица | Поиск `Москва` через Open-Meteo и GeoNames с русским языком ответа |
| Неоднозначность | `Springfield` без страны и с фильтром US; несколько кандидатов не превращаются автоматически в выбор пользователя |
| Неизвестный город | Заведомо искусственный поисковый текст: корректная пустая выдача отдельно от ошибки API |
| Неизвестное место | Искусственное имя музея внутри реально определённого города |
| Фильтр предпочтения | Рестораны с `conditions=vegetarian`; отдельно проверяется принятие запроса и доступные признаки vegetarian в результате |
| Details | Детали одного найденного отеля и одного ресторана, проверка совпадения ID |
| Отклонённые варианты | Локальное исключение по `(provider, external_id)` на живых кандидатах, отсутствие влияния на другую карточку |
| Дубликаты и исчерпание | Удаление одинаковых ID; все отклонены → пустой результат без бесконечного повторного поиска |

Нюанс Geoapify, подтверждённый отдельной проверкой: `place_id` в Details может отличаться от переданного lookup ID. Поэтому сопоставление и локальные отклонения используют `datasource.raw.osm_type + osm_id`, когда эта ссылка доступна, сохраняя также Geoapify ID. Один только одинаковый текст названия/координаты не считается доказательством идентичности. [Официальное пояснение](https://apidocs.geoapify.com/how-to/place-discovery/place-details-by-id-or-coordinates).

**Всего максимум 40 последовательных HTTP-запросов:** 8 Open-Meteo, 8 GeoNames, 24 Geoapify при всех ключах. До пяти объектов на поиск; первые два очищенных примера сохраняются. Geoapify использует только Places с limit≤10 и details-only: плановый максимум **24 кредита**, если условия тарифа не изменились. Основание: [официальный расчёт кредитов](https://www.geoapify.com/pricing-details/), проверен 15.10.2026. Это небольшой функциональный прогон, не нагрузочный тест. Квоту аккаунта скрипт не может проверить за вас.

Пауза — 2 секунды после завершения предыдущего обращения, таймаут сетевой операции — 15 секунд. Автоматических повторов нет. Условия безопасного доступа исходного эксперимента сохраняются. После 401/403/429 дальнейшие обращения провайдеру прекращаются. Overpass, SIX, Frankfurter v1, платные и визовые API в новом сценарии не вызываются.

## Другие режимы

```powershell
# Посмотреть план, не обращаться к API и не создавать отчёт
.\.venv\Scripts\python.exe run_extended.py --plan

# Сначала только Париж: до 17 запросов
.\.venv\Scripts\python.exe run_extended.py --cities paris

# Только основные сценарии Москвы и Суздаля: максимум 15 запросов
.\.venv\Scripts\python.exe run_extended.py --cities moscow suzdal --core-only

# Проверка запуска/отчётов без сети
.\.venv\Scripts\python.exe run_extended.py --offline --no-keys

# Точечная проверка идентичности Search → Details: максимум 5 запросов
.\.venv\Scripts\python.exe run_extended.py --cities paris --details-only

# Все автоматические проверки с искусственными ответами, без сети и без ключей
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

`--max-requests 10` жёстко ограничивает число попыток: после него оставшиеся запросы будут пропущены, а не выдадут полный результат. `--cities` принимает paris/moscow/istanbul/suzdal без повторов. `--limit` — 1–10; `--radius` — 500–3000 метров; `--delay`/`--timeout` — 1–30 секунд. Сетевой timeout не является строгим общим временем всего запуска.

Папки результата те же: `reports/runs/<UTC-id>/` и `data/samples/<UTC-id>/`. Каждый запуск создаёт новую папку и сохраняет старые измерения. Поле `scenario=extended_v2` обозначает текущий расширенный сценарий, `extended_v1` — его первый прогон. Нулевой exit code означает, что отчёт сохранён; число `fail` нужно смотреть в `assessment.md`/`checks.json`.

## Как понимать итог

- **pass** — выполнено конкретное ожидание, например правильная страна и валидные координаты.
- **warn** — результат требует интерпретации: пустая категория, непроверенная локально timezone или недостающий признак фильтра. Это не автоматически неисправность API.
- **fail** — запрос/схема/ожидание не прошли; источник и причина указаны отдельно.
- **skipped** — проверка не выполнена: нет ключа, координат, выбран другой provider, offline либо достигнут предел запросов.

IANA timezone может успешно приходить из API, хотя на Windows не установлена локальная база `tzdata`: тогда проверка имени через `zoneinfo` будет `warn`. Мы не устанавливаем её автоматически. Идентификатор, возвращённый API, остаётся в JSON; отсутствие локальной базы не обнуляет сетевой результат.

Open-Meteo и GeoNames используют общую основу: совпадение ID подтверждает согласованность, а не независимую географическую экспертизу. Координаты берутся из однозначно выбранного населённого пункта текущего ответа. Радиус вокруг него не равен границе города. Для маленького города в радиусе может быть мало объектов.

Отклонение варианта — прикладная операция нашего кода. Поставщик не получает ID карточки и не хранит её отклонения. Проверка не обещает, что после исключения всех пяти результатов появятся ещё пять: будущий подбор/пагинацию нужно проектировать отдельно. Хранение пользователей и карточек остаётся за C# backend.

## Ваше предложение по базовой цене номера

Для ориентировочного бюджета такой режим подходит, если **цена и вместимость действительно известны и зафиксирован их источник**:

```text
номеров = округлить вверх(гости / мест в номере)
оценка проживания = номеров × ночей × цена одного номера за ночь
```

Например, **чисто арифметический пример, не цена реального отеля**: 5 гостей, по 2 места, 3 ночи, условные 100 EUR за номер/ночь → 3 номера → 900 EUR. Расчёт реализован и проверяется автоматически на искусственных данных.

У этого расчёта есть обязательные предпосылки: все номера одного типа, цена одинаковая, размещение группы допускается, дополнительных кроватей/детских условий/ограничений распределения нет. Количество номеров в здании из OSM не является вместимостью одного номера. Стоимость «за человека», «от X», пакет «за весь период» и тариф определённой сезонной даты нельзя без проверки считать базовой ценой комнаты за ночь. Фактическое наличие и итоговые сборы остаются неизвестными.

**Формула готова; источник базовой цены API-проверками не найден автоматически.** Пустую цену мы не заменяем средней по городу или выдуманным значением. Выбор `manual_estimate` означает ручное допущение, а не подтверждение тарифа отеля. Для `official_published_rate`/`historical_average` требуется публичная ссылка и пояснение, к какому номеру/периоду относится сумма. «Средняя» должна иметь реальное основание, не один случайный минимальный тариф.

### Если хотите попробовать расчёт на своих исходных данных

Эти шаги **не нужны для запуска API-проверок** — только для необязательного калькулятора:

1. Скопируйте `data/hotel-estimate.example.json` в `data/hotel-estimate.local.json`. Локальная копия исключена из Git.
2. Укажите `guests`, `guests_per_room`, `nights`: реальные целые положительные значения. Вместимость возьмите из описания конкретного типа номера или явно укажите как ручное допущение.
3. Заполните `price_per_room_night` строкой с точкой, например `"125.50"`, **только своей найденной суммой**. Оставьте `price_basis="room_per_night"`. Нельзя вводить тариф за человека или итог за весь период.
4. Укажите валюту: EUR/RUB/TRY/USD/GBP. Конвертации нет, все цены должны быть в одной валюте; другие валюты с иной точностью пока не поддержаны.
5. Выберите `source_type`: `official_published_rate`, `historical_average` либо `manual_estimate`. В `source_url` вставьте публичную страницу с основанием, а не ссылку на личный кабинет/бронирование. При ручном допущении ссылка может быть `null`.
6. `observed_on` — дата, когда взята цена/сделана оценка, в виде `"2026-10-15"`. В `basis` напишите тип номера, откуда цена и вместимость, сезон/период и ограничения. Не добавляйте ключи API, паспортные или контактные данные.
7. `taxes_included`: `true`, `false` или `null`, если неизвестно. Неизвестные налоги не становятся включёнными.
8. Запустите:

```powershell
.\.venv\Scripts\python.exe run_hotel_estimate.py --input data/hotel-estimate.local.json
```

В PyCharm откройте `run_hotel_estimate.py` и задайте Parameters: `--input data/hotel-estimate.local.json`. Сеть не используется. Путь входного файла разрешён только внутри папки эксперимента; пути относительно файла запуска, а не произвольной рабочей папки.

Результат — `reports/estimates/<UTC-id>/estimate.md` и JSON. В нём явно записано: оценка, источник/дата, допущения, `is_live_offer=false`, `availability=null`. Шаблон с незаполненными `null` не рассчитывается. Это отдельный результат и он не записывается как ответ гостиничного API.

## Что ещё потребуется от команды

Для этого этапа API-проверок — **ничего, существующих ключей достаточно**. OpenTripMap можно добавлять позже, если после анализа будет принято решение исследовать описания/изображения. Его работа не гарантирует цены, фото всех объектов или отзывы.

После расширенного отчёта нужно согласовать обязательные поля интерфейса (можно ли без фото/рейтинга/цены), целевые страны/города, срок обновления данных и допустимость оценочного режима проживания. Базовая цена и настоящая цена на даты должны быть разными состояниями карточки. Визы и партнёрский доступ к бронированию остаются отдельными решениями.

Первичные контракты дополнительных фильтров проверены 15.10.2026: [GeoNames Search](https://www.geonames.org/export/geonames-search.html), [Geoapify Places](https://apidocs.geoapify.com/docs/places/), [Open-Meteo Geocoding](https://open-meteo.com/en/docs/geocoding-api). Основные условия и атрибуция сохранены в [реестре источников](reports/sources.md).
