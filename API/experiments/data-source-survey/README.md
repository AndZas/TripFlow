# Эксперимент с источниками данных TripFlow

**Новый этап:** [расширенные проверки четырёх городов и инструкция](EXTENDED.md). Запуск в PyCharm: `run_extended.py`, те же локальные ключи. Исходный `run_survey.py` сохраняет демонстрационный сценарий Парижа. Калькулятор оценки по введённой базовой цене номера описан отдельно в той же инструкции.

**Уже выполненные дополнительные проверки:** [понятный отчёт о результатах](reports/extended-findings.md), включая Geoapify/GeoNames с ключами и найденные ограничения.

Для выбора полей и сокращения числа запросов используйте [сводку API: фильтры, поля и заполненность](API_DATA_SUMMARY.md).

Начните с **[сравнительного отчёта](reports/comparison.md)**: там есть решение по каждому кандидату, измерения и ограничения. Это самостоятельный эксперимент, не часть приложения. Проверка документации и живые запуски: **15 октября 2026 года, Москва**.

## Быстрый запуск в Windows / PowerShell

Откройте терминал в этой папке:

```powershell
cd F:\Files\PythonProjects\TripFlow\API\experiments\data-source-survey
py -3.14 -m venv .venv
.\.venv\Scripts\python.exe run_survey.py --no-keys
```

Если `.venv` уже создано, достаточно последней команды. Зависимостей нет: используется стандартная библиотека Python 3.14; `requirements.txt` фиксирует это. Ничего устанавливать глобально и активировать окружение не нужно. Скрипт проверен на Python **3.14.0 / Windows**. На 3.13 совместимость предполагается, но отдельно не проверена.

## Запуск в PyCharm

1. Откройте папку `data-source-survey` как проект либо оставьте открытым TripFlow/API.
2. В **Settings → Project → Python Interpreter → Add Interpreter → Add Local Interpreter → Existing** выберите `data-source-survey\.venv\Scripts\python.exe`. При создании нового окружения используйте Python 3.14 и эту же папку `.venv`.
3. Откройте **`run_survey.py`**, нажмите **Run**. Все пути вычисляются от расположения файла; рабочая папка не влияет на место сохранения.
4. В **Run → Edit Configurations → Parameters** задайте `--no-keys` для гарантированного запуска без ключей. Для показа JSON в консоли добавьте `--show-samples`.
5. В конце консоль напечатает пути к отчёту и примерам нового запуска.

Эксперимент не использует родительское окружение `API\.venv` и не читает произвольные конфигурации приложения. PyCharm не нужно настраивать доступ к секретам через аргументы запуска.

## Что выполняется

Без ключей: один поиск Парижа в Open-Meteo; пять небольших запросов Overpass (музеи, история, природа, рестораны, жильё); два запроса EUR/RUB к Frankfurter v2/v1; справочники SIX и CLDR. Максимум **11 HTTP-запросов**, строго последовательно. Объекты: до 10 на категорию по умолчанию. Пауза между завершением одного запроса и началом следующего — минимум 2 секунды. Таймаут сетевой операции — 20 секунд. Это не строгий общий deadline всего запуска: DNS и несколько операций чтения могут его увеличивать.

С ключами дополнительно: Geoapify до 5 поисков + 2 details; OpenTripMap до 4 поисков + 2 details; GeoNames до 3 запросов. Для первых двух нужен явный признак бесплатного тарифа. Это подтверждение уже доступного локального тарифа, а не переключение подписки. Скрипт не знает остаток вашей квоты: включайте источник только после проверки остатка в кабинете. При HTTP 401/403/429 следующие запросы к тому же провайдеру пропускаются. Автоповторов и переключения на другие публичные серверы нет.

Поиск POI использует координаты столицы Франции из текущего ответа Open-Meteo. Если их нет, зависимые запросы пропускаются. Радиус 3 км не равен административной границе Парижа. Отбор первых N объектов Overpass не означает «лучшие N» или ближайшие N.

Amadeus, Google, Foursquare, Tripadvisor, Yelp, Booking, Expedia и визовые поставщики **не вызываются**; причины видны в каждом отчёте. Для Amadeus Self-Service доступ закрыт. Для остальных отсутствует подтверждённый бесплатный доступ либо предусмотрено исследование документации. Визовые профили не отправляются.

## Ключи: только локально

```powershell
Copy-Item .env.example .env
```

Заполните `.env` в этой папке в локальном редакторе. Файл исключён из Git. Или задайте переменные в настройках окружения PyCharm. Переменные процесса имеют приоритет над `.env`; используется простой формат `NAME=value`, без подстановок и многострочных значений.

| Переменная | Для чего |
|---|---|
| `GEOAPIFY_API_KEY` | Free key из MyProjects |
| `GEOAPIFY_FREE_PLAN=1` | Вы проверили, что ключ относится к Free и квота доступна |
| `OPENTRIPMAP_API_KEY` | Локальный ключ OpenTripMap |
| `OPENTRIPMAP_FREE_PLAN=1` | Подтверждён некоммерческий Free и остаток квоты |
| `GEONAMES_USERNAME` | Собственный активированный бесплатный webservice username; `demo` запрещён |

Без этих переменных запуск работает. `--no-keys` не читает `.env` и не использует перечисленные ключи из окружения. Ключи других кандидатов сейчас не нужны и не обрабатываются.

## Режимы

```powershell
# Полный запуск без ключей, с небольшими JSON в консоли
.\.venv\Scripts\python.exe run_survey.py --no-keys --show-samples

# Только город, валютный справочник и курс
.\.venv\Scripts\python.exe run_survey.py --no-keys --providers open_meteo cldr frankfurter

# Проверка бесплатного Geoapify после заполнения .env
.\.venv\Scripts\python.exe run_survey.py --providers open_meteo geoapify

# Уточнение одного запроса Overpass; меньший радиус меняет выборку
.\.venv\Scripts\python.exe run_survey.py --no-keys --providers open_meteo overpass --categories hotels --radius 500 --delay 5 --timeout 30

# Без сети: проверка запуска, путей и отчёта о пропусках
.\.venv\Scripts\python.exe run_survey.py --offline --no-keys

# Автоматические проверки с искусственными ответами, без внешних API
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Для POI включайте `open_meteo` в `--providers`; иначе поиск пропустится из-за отсутствия проверенных координат. `--categories` применяется к Overpass, Geoapify и OpenTripMap. `--limit`: 1–20; `--radius`: 500–3000 метров; `--delay`: 1–30 секунд; `--timeout`: 1–30 секунд. При отсутствии аргументов используется весь безопасный сценарий.

## Где смотреть результаты

- `reports/comparison.md` — подготовленный аналитический отчёт; скрипт его не переписывает.
- `reports/api-contracts.md` — параметры и границы данных для дальнейшей разработки.
- `reports/sources.md` — официальные документы, дата проверки и замеченные изменения.
- `reports/runs/<UTC-id>/results.json` — машинная сводка каждого запуска.
- `reports/runs/<UTC-id>/live-results.md` — параметры, статусы, длительность, поля и заполненность.
- `data/samples/<UTC-id>/*.json` — первые два очищенных объекта и нормализация, когда она предусмотрена.

Каждый запуск создаёт собственную папку и не затирает прошлые измерения. UTC в имени может соответствовать предыдущему календарному дню в Москве. Идентификаторы выполненных запусков приведены в отчёте. Ранние запуски были сделаны по мере разработки; в них ещё нет некоторых позднее добавленных адаптеров и отметок времени по каждому endpoint. Их сетевые измерения сохранены без подмены.

`ok` = получен разбираемый ответ нужной формы; `empty` = пустое тело/выборка; `http_error` = ошибка HTTP; `network_error` = нет полного ответа (например, timeout/TLS); `provider_error` = ошибка в HTTP 200; `schema_error` = неожиданная структура; `skipped` = запрос не выполнялся. `count=null` означает «не измерено», не ноль результатов. Код завершения 0 означает, что отчёт записан, и не гарантирует работоспособность всех API.

В нормализации отсутствующие факты остаются `null`. `fee=yes` не превращается в цену билета, каталог отелей — в наличие номера, а `rate` OpenTripMap — в пользовательский рейтинг. Ссылка на сайт очищается от query/fragment и может потерять часть адреса динамической страницы. Телефоны, email и OSM user/uid не сохраняются. Полная сырая выгрузка остаётся только в памяти на время обработки.

Если возникают `SSLCertVerificationError`, 403 или 429, изучите статус и причину в отчёте. Проверка сертификатов включена; обход блокировок и исправление системного хранилища доверия этим экспериментом не выполняются. В среде Codex для исходящих запросов потребовалось разрешение сети; после разрешения измерения выполнены. Окружение успешно создано после повторного запуска вне изолированной среды. В изолированных локальных проверках Python печатал `Failed to find real location ...`, но проверки завершились успешно; обычные разрешённые запуски этой строки не выдавали.
