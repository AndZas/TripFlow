# Локальный подбор TripFlow с одним вызовом модели

13 ноября 2026 года

## Что изменилось

В [новом харнесе](planned_search.py) LM Studio возвращает параметры `search_trip`. Модель выбирает категории и извлекает упоминание конкретного места и план платных визитов. Python проверяет аргументы, применяет лимиты и исключения, сортирует отели по цене и связывает название места с единственным совпадением в выдаче поставщика. Дни, количество путешественников, цены и ID остаются в коде. Для одного визита в день на четыре дня Python берёт `daily/1` и считает четыре визита на человека. Если число неясно, в прототипе сохраняется `null`.

Режим «только бесплатное» пропускает только подтверждённую нулевую цену. В имеющемся снимке таких мест нет, поэтому результат пуст. Пустой список категорий выражает явный отказ от поиска. Для догенерации бюджет остаётся прежним. Проверка исключения всё ещё использует внутренние ID эксперимента. Реальный API потребует сопоставления по имени и координатам.

## Сравнение

В каждой полной серии 28 карточек. Взяты 23 ранее проверенных запроса и добавлены пять новых формулировок, в том числе уточнение с отменой исходной категории, несколько чисел в одном тексте и разные планы участников. Два сценария помечены как ограничения данных или модели бюджета: неизвестная детская кроватка и разное число посещений у участников. Они исключаются из знаменателя проверяемых сценариев, но результаты интерпретации сохраняются. Запросы шли последовательно с паузой 5 секунд. Медианы исключают паузу и загрузку модели.

Qwen3.5-9B GGUF `Q4_K_M` добавлена в существующий каталог LM Studio. Размер файла 5,63 ГБ, SHA-256 `cd76ec205963b3b33350093e6904d9de16c4e666fd104e1f632d25c7f15f2a13`. На RTX 5060 Ti с 8 ГБ модель загрузилась с контекстом 4096, одним слотом и `--gpu max`. Общая занятость GPU после загрузки составила 6451 из 8151 МиБ. [Вес модели](https://huggingface.co/lmstudio-community/Qwen3.5-9B-GGUF)

При первом запуске Qwen3.5 продолжала генерировать рассуждения с `chat_template_kwargs.enable_thinking=false` и упиралась в лимит. [Диагностический журнал](runs/plan-qwen35-9b.jsonl) остановлен досрочно. На установленном сервере короткий пробный вызов подтвердил, что `reasoning_effort: "none"` отключает этот режим. Полные прогоны без рассуждений используют этот параметр.

Первую серию 4B пересчитал по единой проверке `freeOnly`. В первоначальном JSONL этот критерий отсутствовал. Одно формально успешное пожелание «в платные музеи не пойдём» ошибочно превращалось в фильтр бесплатности для всех мест. В строках таблицы применяется один критерий ко всем моделям.

На тех же запросах 9B лучше сохранила число после исправления «два музея → три выставки» и вернула `unknown` для разных планов участников. При этом обе модели путали «один на каждого» с «один каждый день» и включали парк после «парки и мемориалы пропустим». Простое добавление правил для 4B изменило набор ошибок без роста общего результата.

У короткого промпта и классификатора догенерация отеля по цене и исключениям выполнялась без вызова модели. Медиана рассчитана по карточкам с HTTP-запросом. Переключение с вызова функции на [ответ по JSON Schema](runs/plan-qwen35-9b-json.jsonl) прошло 1 из 6 целевых карточек. Модель вернула допустимый JSON, но пропускала ограничения и однажды указала несовместимые значения полей, которые Python отклонил. Выборка из шести случаев отобрана для диагностики и не сравнима напрямую с полными сериями. [Структурированный вывод LM Studio](https://lmstudio.ai/docs/developer/openai-compat/structured-output)

[Режим рассуждений 9B](runs/plan-qwen35-9b-reasoning.jsonl) прошёл 2 из 6 выбранных карточек, медиана 9,95 с. На тех же шести карточках режим без рассуждений прошёл одну. Рассуждения помогли с явным отказом от подбора, но не исправили отрицания и частоту посещений. Из-за задержки и оставшихся ошибок этот режим не выбран по умолчанию.

## Когда нужно подтверждение

Схема ограничивает допустимые значения, но оба варианта `trip/1` и `daily/1` формально корректны. Если их перепутать, оценка меняется кратно длительности поездки. Для следующего прототипа предусмотрен шаг, на котором пользователь видит выбранные категории, режим бесплатности и план посещений. Подтверждённые поля передаются отдельно и имеют приоритет. Затем Python повторно проверяет уже применённые параметры и считает сумму.

В [planned_search.py](planned_search.py) этот шаг проверяется на имитации структурированных полей. Команда с `--confirmed` сохраняет отдельно исходный план модели, поля подтверждения и итог. Интерфейс и межсервисный контракт в этом эксперименте не менялись.

[Четыре повтора с подтверждёнными полями](runs/plan-qwen35-9b-confirmed.jsonl) прошли 4/4. На карточке друзей модель предложила один визит в день. Подтверждение «один за поездку» изменило оценку с 6 012 ₽ на 2 004 ₽ для четверых. В остальных трёх случаях код применил подтверждённые категории, снял ошибочный фильтр бесплатности для парков и памятников и сохранил ноль платных визитов при отказе от подбора. Эти четыре входа проверяют приоритет полей. Они не измеряют точность модели или удобство реального экрана подтверждения.

## Выбор для следующей реализации

Из проверенных конфигураций основной кандидат — **Qwen3.5-9B Q4_K_M с промптом `examples` и вызовом `search_trip`**. Он лучше прошёл общий набор, помещается на тестовой видеокарте и требует одного запроса модели на карточку. Qwen3 4B остаётся более быстрой альтернативой для среды с меньшим объёмом памяти. Смысловой риск остаётся у обеих моделей. Категории и план визитов стоит показывать как предложение перед применением обязательных ограничений и расчётом бюджета. Однозначную фильтрацию отеля по цене и исключениям можно выполнить напрямую.

Пока покрыты категории мест, уточнения, точное имя из выдачи, строгая бесплатность, цена отеля при догенерации и расчёт музейной части бюджета. Снимки относятся к Москве и не дают подтверждения отельных удобств или доступности на даты. Общий бюджет, отдельные планы участников, живой поиск поставщиков, полноценное ранжирование и callback в C# остаются за пределами этого прототипа. Облако в эксперименте не использовалось.

## Воспроизведение

Из папки эксперимента при работающем LM Studio:

```powershell
& ~/.lmstudio/bin/lms.exe load qwen3.5-9b --context-length 4096 --parallel 1 --gpu max --identifier tripflow-qwen3.5-9b -y
.\.venv\Scripts\python.exe -X utf8 -m unittest -q
.\.venv\Scripts\python.exe -X utf8 planned_search.py --model tripflow-qwen3.5-9b --variant examples --output runs/plan-replay.jsonl
.\.venv\Scripts\python.exe -X utf8 planned_search.py --model tripflow-qwen3.5-9b --variant examples --confirmed --output runs/plan-replay-confirmed.jsonl
```

По умолчанию используется порт 1234 и пауза 5 с. Указывать новый путь вывода. Для сравнения промптов доступны `--variant strict`, `compact`, `classifier`; для отдельных проверок `--case`, `--transport json` и `--reasoning`.

Все 18 тестов Python прошли. В 156 завершённых прогонах карточек ошибок HTTP не зарегистрировано. Дополнительно сохранены три прерванных диагностических прогона с лимитом генерации. Все журналы и изменения остались локальными.
