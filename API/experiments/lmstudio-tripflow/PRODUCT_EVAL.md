# Qwen3-4B на карточках, похожих на TripFlow

13 ноября 2026 года

## Условия

Qwen3-4B-Instruct-2507 `Q4_K_M` запущена в LM Studio на RTX 5060 Ti 8 ГБ. Контекст 4096 токенов, один слот инференса, температура 0. Сервер получает по одному запросу с паузой минимум 2 с между ответом и следующим запросом внутри карточки и 5 с между карточками. Время HTTP в журнале исключает эти паузы. Статистика не моделирует нагрузку от нескольких пользователей и не объясняет причину замедлений в предыдущей серии.

[Набор запросов](product_suite.py) включает 15 полных генераций, три догенерации и пять дополнительных формулировок для проверки переноса. У карточек есть даты, размер группы, бюджет и ожидаемый размер выдачи. Проверяются выбранные категории, интерпретация числа платных музеев, приоритет названного места, исключения и гостиничный лимит. Результат каждой карточки включает проверенную выдачу и её срез по запрошенному количеству. Срез имитирует часть ответа, которую увидит пользователь. Отчёт не проверяет весь callback.

Для воспроизводимости используются сохранённые реальные ответы Russhotels и Geoapify по Москве и городская музейная ставка Росстата. Выборка небольшая, цены гостиниц на даты не подтверждены. Полный бюджет, применение целевого бюджета при полной генерации, полнота поиска поставщика, вычисление `hasMore` и отправка callback в этом опыте отсутствуют. Сценарий с низким целевым бюджетом проверяет реакцию на входной контекст и пригодность выдачи для дальнейшего расчёта. Он не доказывает реализацию бюджетного подбора по контракту. [Контракт](../../CONTRACT.md)

Ожидания записаны в сценариях до оценки. Для диапазона или разных планов участников ожидается `null` как сигнал о недостаточности единого числа. Это правило эксперимента. В интерфейсе потребуется решение команды о запросе уточнения или использовании предварительной оценки. Четыре сценария отдельно отмечены как ограничения данных или представления запроса. У каждого при этом сохраняются результаты тех проверок, которые провести удалось.

## Что сломалось в исходном харнесе

[Исходный прогон](runs/product-baseline.jsonl) прошёл **9 из 14 поддерживаемых сценариев**. Если считать также четыре сценария с пробелами в данных и схеме, полностью прошли **9 из 18**. Сбоев HTTP не было. Медиана суммарного времени HTTP на карточку составила 2,47 с.

| Сценарий | Что вернула модель | Последствие |
|---|---|---|
| «В приоритете выставки, парки и мемориалы пропустим» | Все три категории | Схема и проверка ID пропускают неподходящую выдачу. Ошибку обнаруживает проверка по смыслу |
| «Два или три платных музея» | `2` | Неопределённый план превращается в фиксированную сумму |
| «Один участник из троих хочет в два музея» | `2` на человека | При ставке 501 ₽ харнес даёт 3 006 ₽ вместо 1 002 ₽ для этого плана |
| «По одному музею в день, включая обе даты» | `2` вместо `4`, а также ID `nature- 2` | Ответ отклонён по ID. Ошибка числа видна в сыром JSON |
| «Поставьте “100 лет сатиры” первой, цену не знаем» | Верный первый объект, `1` платный визит | Ставка применена при неподтверждённой платности |
| «Оставь музеи, добавь памятники» при догенерации | Верные категории, `0` визитов при отсутствии ставки | Харнес отклонил ответ. Догенерация мест не меняет бюджет |

Примеры «без музеев», «только парки после уточнения», «три выставки вместо двух музеев» и «один визит на каждого из четырёх» показывают, что короткие формулировки и некоторые исправления модель обрабатывает. При выборе конкретного места она корректно подняла памятник Цветаевой на первое место. Граница гостиничного лимита тоже выдержана. Здесь сам фильтр выполняет код.

Четыре ограничения, которые смена модели сама по себе не устранит:

- Для детской кроватки в снимке поставщика нет подтверждения.
- Для запроса «только бесплатное» у кандидатов отсутствуют известные цены, а инструмент не передаёт режим строгого отбора. Ноль в общей оценке не доказывает бесплатность кандидата.
- Отказ от всех достопримечательностей нельзя выразить через текущий обязательный вызов с непустым списком категорий.
- Один параметр «посещений на человека» предполагает общий план всей группы и не выражает отдельные планы участников.

## Что меняет промпт

[Те же 18 карточек с более явными правилами](runs/product-explicit-rules.jsonl) дали **7 из 14 поддерживаемых**, или 7 из 18 с ограничениями. Медиана HTTP составила 2,53 с. Модель перестала считать вход на конкретную выставку платным по умолчанию и в случае «два или три» оставила число неизвестным. В последнем сценарии она при этом потеряла парк. Для «парки и мемориалы пропустим» опять выбрала парк. Кроме `nature- 2` появились `museums-_2` и `historic- 2`. При догенерации модель дважды заполнила поле бюджета, хотя ставка для этой операции отсутствовала.

Результаты показывают, что длинный промпт меняет распределение ошибок и требует повторной проверки всего набора. Исправление одной фразы не гарантирует сохранения поведения на остальных.

В [пяти дополнительных формулировках](runs/product-holdout.jsonl) прошли три. Модель правильно разобрала отмену платных выставок, один неопределённый диапазон и один запрет категорий. В тексте с несколькими числами она пропустила парк и вернула `null` вместо трёх посещений. В другом запросе вернула два визита вместо трёх, хотя была дана инструкция учитывать обе даты.

## Что меняет ограничение схемы

В [целевом повторе](runs/product-constrained.jsonl) итоговый JSON разрешает только известные ID через `enum`, а в догенерации поле бюджета принимает только `null`. Проверка полного набора ID в Python сохранена, чтобы отлавливать дубликаты. Прошли **3 из 5** ранее проблемных сценариев. Исправились ошибки копирования ID и заполнения бюджета в догенерации. На четырёхдневной поездке модель вернула четыре посещения, но на трёхдневной снова вернула два вместо трёх. Парк в запросе «если останется время» снова выпал. Пять повторов служат диагностикой этих ошибок.

Всего отправлено **170 HTTP-запросов в 46 прогонах 23 уникальных карточек**. Сетевых ошибок и ошибок HTTP не зарегистрировано. Медиана суммарного времени HTTP по сериям была около 2,5 с на карточку. В эти цифры входят ответы с неверной интерпретацией и отклонённые ответы. Интервалы запуска и работа поставщиков исключены из замера.

## Рекомендация для MVP

Оставить Qwen3-4B локальным вариантом для разработки и демонстрации. Подтверждена работа инструментов и простых рекомендаций, в том числе приоритет конкретного известного места. При свободном вводе модель пока ненадёжна как единственный источник обязательных ограничений и параметров бюджета. Результат в корректном JSON может содержать искажённый смысл, который валидатор формата не видит.

Для следующего среза стоит закрепить обязанности за кодом и моделью:

1. **Python** определяет шаги, дни и ночи, применяет жёсткие фильтры и исключения, выбирает известные ID, считает цены. Для догенерации схема решения вообще может обходиться без поля бюджета.
2. **Qwen** предлагает категории и интерпретацию пожеланий. Для «по одному музею в день» полезно просить модель извлечь частоту, а количество дней брать из дат в Python. Для диапазона, разного плана участников и неизвестной цены следует хранить неопределённость до уточнения или применения согласованного правила.
3. **Интерфейс или backend** фиксирует обязательные ограничения явно, если их нельзя безопасно вывести из свободного текста. Например, отдельное «только подтверждённо бесплатное» позволяет Python исключить места с неизвестной ценой. Признаки, которых нет у поставщика, должны оставаться неизвестными.

Облако сейчас не требуется для продолжения разработки. Данных для вывода, насколько облачная модель точнее, нет. Сначала имеет смысл проверить локальную модель с более узким выводом. Если на новых запросах всё ещё будут повторяться ошибки отрицания, уточнений и параметров бюджета, сравнить более сильную локальную или облачную модель на тех же входах, источниках и проверках. Решение о смене модели стоит привязать к доле смысловых ошибок и времени карточки на целевой машине. Замена модели сама по себе не даст отсутствующих сведений у поставщика.

## Как воспроизвести

В PowerShell из папки эксперимента с работающим LM Studio:

```powershell
.\.venv\Scripts\python.exe -X utf8 product_suite.py --output runs/product-replay-baseline.jsonl
.\.venv\Scripts\python.exe -X utf8 product_suite.py --variant explicit-rules --output runs/product-replay-rules.jsonl
.\.venv\Scripts\python.exe -X utf8 product_suite.py --holdout --variant explicit-rules --output runs/product-replay-holdout.jsonl
.\.venv\Scripts\python.exe -X utf8 product_suite.py --variant constrained-decision --case friends-weekend --case museum-per-day --case refine-add-history --case range-not-exact --case holdout-arrival-departure --output runs/product-replay-constrained.jsonl
```

`--case` позволяет выбрать конкретный сценарий, `--request-interval` и `--case-interval` меняют паузы. Путь вывода должен быть новым. Журнал содержит вход, ожидания, полученные вызовы, ответы модели, результаты проверок и причину ошибки. HTTP-ошибки, ответы, отклонённые валидатором, и неверные интерпретации отмечаются отдельно.
