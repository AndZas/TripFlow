# TripFlow · Python API

FastAPI-сервис принимает задачи подбора и расчёта сметы. Текущая версия возвращает вымышленные отели и места Москвы и использует тестовые бюджетные ставки.

## Размещение на Render

Создайте Web Service и PostgreSQL в одном регионе. Для первого размещения используйте пустую базу. Бесплатная Render Postgres истекает через 30 дней. [Условия тарифа](https://render.com/docs/free#30-day-limit)

| Поле Web Service | Значение |
|---|---|
| Branch | `deploy/api` |
| Language | Docker |
| Root Directory | Оставить пустым |
| Dockerfile Path | `API/Dockerfile` |
| Docker Build Context Directory | Корень репозитория (`.`) |
| Health Check Path | `/health` |
| Auto-Deploy | On Commit |

Dockerfile читает `shared/data/destinations.json` из общего каталога, поэтому контекст сборки должен включать весь репозиторий. Контейнер слушает выданный Render порт `PORT`. [Docker на Render](https://render.com/docs/docker) · [Автоматический деплой](https://render.com/docs/deploys#auto-deploys)

В Environment веб-сервиса укажите `DATABASE_URL` со значением **Internal Database URL**. Для создания владельца в пустой базе временно задайте `TRIPFLOW_PORTAL_ADMIN_EMAIL` и новый `TRIPFLOW_PORTAL_ADMIN_PASSWORD`. После первого успешного входа на `/portal` удалите эти две переменные и примените изменения. Аккаунт и его роль сохранятся в PostgreSQL. [Подключение PostgreSQL](https://render.com/docs/postgresql-creating-connecting)

После успешного деплоя откройте `/health` и `/portal` по адресу веб-сервиса. Когда одобрите заявку и выпустите ключ, проверьте полный цикл создания и чтения задачи через `/docs`.

## Выпуск новой версии

Рабочие изменения команды продолжают попадать в `main`. Render следит за `deploy/api`. После проверки версии из чистого рабочего дерева обновите ветку размещения выбранным коммитом из `main`.

~~~powershell
git fetch origin
git switch deploy/api
git merge --ff-only origin/deploy/api
git merge --ff-only origin/main
git push origin deploy/api
git switch main
~~~

Этот вариант выпускает текущую версию `origin/main`. Чтобы выпустить более ранний проверенный коммит, укажите его SHA вместо `origin/main` во второй команде merge. Если ветка размещения ещё не создана локально, используйте `git switch --track origin/deploy/api` при первом выпуске.

## Кабинет разработчика

1. Разработчик открывает кабинет, выбирает «Запросить доступ» и задаёт email и пароль. При попытке входа он видит статус заявки.
2. Владелец и администраторы рассматривают обычные заявки. Владелец назначает администратора из одобренных разработчиков и может снять эту роль. Администратор видит только аккаунты разработчиков.
3. При отключении сессии и ключ отзываются, роль администратора снимается. Для восстановления пользователь заново подаёт заявку с прежними email и паролем. Её рассматривает владелец. История задач и метрики остаются в аккаунте.
4. Одобренный разработчик выпускает один ключ. Полное значение показывается при выпуске. Перевыпуск и отзыв сразу отключают прежний ключ.
5. В карточке аккаунта откройте «Активность API». Видны число запросов за 24 часовых интервала, запуски, опросы, HTTP-ошибки и максимальное число запросов за час за семь дней. Учитываются запросы с действующим ключом после обновления. Расчёт задач и чтение их результатов видны раздельно. Счётчики измеряют нагрузку, квот на API нет.

## Письма об одобрении

В бесплатном тарифе Resend доступны 100 писем в сутки и 3 000 в месяц. Для писем членам команды нужен домен, где вы можете менять DNS. Если домена ещё нет, его регистрация может стоить денег. [Тарифы Resend](https://resend.com/pricing)

1. В Resend откройте **Domains → Add Domain**, добавьте свой домен или поддомен и внесите у DNS-провайдера записи, которые покажет Resend. Дождитесь статуса **Verified**. На подтверждённом домене можно выбрать адрес отправителя без отдельного почтового ящика. [Настройка домена](https://resend.com/docs/dashboard/domains/introduction)
2. В **API Keys → Create API Key** выпустите ключ с доступом **Sending access** и запишите его в `RESEND_API_KEY` в Environment веб-сервиса Render. В `TRIPFLOW_EMAIL_FROM` укажите, например, `TripFlow <notifications@mail.example.org>` с вашим подтверждённым доменом. [Ключи Resend](https://resend.com/docs/dashboard/api-keys/introduction)
3. Без домена можно проверить отправку с `onboarding@resend.dev` на email аккаунта Resend. После одобрения результат отправки появится в панели. [Ограничения тестового отправителя](https://resend.com/docs/knowledge-base/403-error-resend-dev-domain)

Приложение отправляет письмо по HTTPS сразу после одобрения. На Render письмо включает ссылку на кабинет. При сбое отправки доступ уже открыт, а в карточке аккаунта доступна кнопка повтора.

## Проверка в Swagger

Откройте Swagger UI по пути `/docs`, нажмите **Authorize** и вставьте выпущенный ключ. В `POST /v1/recommendations` выберите пример «Отели» или «Достопримечательности», затем **Try it out → Execute**. В `POST /v1/budget` есть пример сметы. У каждого примера свой `taskId`.

POST отвечает `202`. Выполните `GET /v1/tasks/{taskId}` с тем же ключом. При `pending` повторите через указанное в `Retry-After` число секунд. При `completed` читайте `result`. Мок может завершиться уже к первому GET. Новый набор входных данных требует нового ID. C# достаточно исходящего HTTPS к Python API. [Контракт и примеры](docs/BACKEND-HANDOFF.md)
