# TripFlow — Python API и исследования источников

В `API/` собраны материалы Python-направления TripFlow. Здесь находятся исследования внешних источников данных и небольшой локальный расчёт стоимости проживания. Это подготовка к проектированию Python API, а не готовый production-сервис и не утверждённый контракт приложения.

## С чего начать

1. Откройте **[README эксперимента](experiments/data-source-survey/README.md)**: там описаны запуск, режимы, настройки и структура файлов.
2. Для быстрого понимания результатов прочитайте **[сводку полей и источников](experiments/data-source-survey/API_DATA_SUMMARY.md)**.
3. Для подтверждённых дополнительных сценариев и практических рекомендаций смотрите **[расширенный отчёт](experiments/data-source-survey/reports/extended-findings.md)**.

## Что показал эксперимент

- **Geoapify Places** — наиболее полезный из проверенных источников для каталога музеев, исторических мест, природы, ресторанов и объектов размещения. В выборке из 100 объектов координаты и адресная строка присутствовали у всех; сайты — у 27%, фотографии — у 3%, описания — у 3%. Числовых цен и доступности гостиничных номеров не было.
- **GeoNames** подходит для поиска города и справочных сведений о стране, валюте и часовом поясе. **Open-Meteo Geocoding** проверен как альтернатива для поиска города и координат.
- **CLDR** можно использовать как локальный справочник валют. **Frankfurter v2** пригоден для справочного обменного курса, когда он нужен; это не курс конкретного бронирования.
- Бесплатный каталог объектов не решает задачу реальных цен и наличия гостиниц. Для этого потребуется отдельный источник предложений либо отдельная, явно помеченная оценка с известным основанием.

Это выводы небольших исследовательских запусков, а не окончательные архитектурные решения. Масштаб, условия использования источников и продуктовые требования нужно учитывать при дальнейшем проектировании.

## Материалы эксперимента

В [`experiments/data-source-survey/`](experiments/data-source-survey/README.md) находятся:

- скрипты для основного и расширенного запусков;
- протокол и первоначальная задача исследования;
- отчёты сравнения, полей API, источников и проверок;
- датированные JSON-результаты запросов и небольшие очищенные примеры;
- локальный калькулятор оценки проживания, который не подставляет неизвестную цену.

В [`experiments/free-api-gap-test/`](experiments/free-api-gap-test/README.md) находится дополнительная проверка Geoapify Geocoding, OpenTripMap, TRY/RUB у Frankfurter и условного этапа Wikidata/Commons. Её [оценка](experiments/free-api-gap-test/reports/assessment.md) содержит актуальные выводы и ограничения; [официальные тарифы и документация](experiments/free-api-gap-test/reports/sources.md) собраны отдельно. Запуск, требующий API-ключей, выполняется только по явному флагу `--live`.

Расширенный этап включал **45 живых API-запросов**: 40 в полном прогоне и 5 в отдельной проверке идентичности объектов между поиском и Details. В отчёте проверки кода зафиксировано **40 автоматических тестов, OK**. Параметры и ограничения каждого запуска описаны в его папке `reports/runs/`.

## Повторный запуск

Для запуска без ключей достаточно открыть папку эксперимента и выполнить команду:

```powershell
py -3.14 -m venv .venv
.\.venv\Scripts\python.exe run_survey.py --no-keys
```

Для расширенного сценария и настройки ключей используйте инструкцию [README эксперимента](experiments/data-source-survey/README.md) и [EXTENDED.md](experiments/data-source-survey/EXTENDED.md). Локальный `.env` и виртуальные окружения исключены из Git; пример переменных хранится в `.env.example`.
