# TripFlow · Эксперимент с карточкой поездки

Рабочая папка для команд и файлов стенда — `API/experiments/card-preferences`.

Локальный стенд связывает разбор пожеланий с подбором отелей и мест, проверкой условий по источникам и оценкой расходов. Модель эксперимента — Qwen3.5‑9B в LM Studio. На первом этапе модель получает только текст пожеланий длиной до 2000 символов.

[Итоги эксперимента](REPORT.md) и [сводка контрольных прогонов](../../../experiments/card-preferences/results.json) входят в репозиторий. Новые журналы команд записываются в локальную папку `runs/`.

Ниже описано поведение локального стенда, включая поштучный показ в браузере. В текущем FastAPI пакет по задаче доступен целиком после `completed`. [Опрос задач и завершение выдачи](../../ARCHITECTURE.md#опрос-задач-и-завершение-выдачи)

## Что делает эксперимент

1. Классифицирует каждый признак пробного словаря как обязательный, желательный, исключённый, нежелательный или неуказанный. Категории мест — музеи, парки, исторические места. Признаки отелей — ресторан, парковка, Wi-Fi. Для действующего фильтра Python проверяет цитату и собирает строгость и признак исключения. Если признак упомянут, но был пропущен или цитата не согласуется с классификацией, модель получает короткий запрос на перепроверку. Поддержку каждого признака ещё нужно сверить с поставщиком.
2. Выбирает фрагменты текста для питания, транспорта, прочих трат и резерва. Модель возвращает номера фрагментов. Python сохраняет текст из исходного ввода, включая суммы и их единицы. Для отсутствующих пожеланий Python ставит `null`.
3. Для каждого дополнительного условия отдельно генерирует короткую подпись, вопрос, поисковые слова и три текста для `confirmed`, `contradicted` и `unknown`. Поисковая фраза собирается функцией `search_query` из ключевых слов и данных конкретного отеля.

У каждого запроса своя схема. Python проверяет сочетания полей, неизвестные значения, дубли и длины строк. Подбор и проверка по источникам описаны ниже.

## Запуск

### Конструктор карточки в браузере

Запусти сервер LM Studio, затем открой [start-stand.cmd](../../../experiments/card-preferences/start-stand.cmd) двойным кликом. Из PowerShell в рабочей папке стенда можно выполнить ту же команду.

```powershell
.\start-stand.cmd
```

Скрипт использует локальное окружение эксперимента, загружает установленную Qwen3.5‑9B и открывает [страницу стенда](http://127.0.0.1:8765/). Для выдачи мест используется переменная Windows `GEOAPIFY_API_KEY`. Москва берётся из общего справочника TripFlow. Санкт-Петербург, Казань, Нижний Новгород, Екатеринбург и Ярославль добавлены в [список для стенда](../../../experiments/card-preferences/stand-destinations.json). Кнопка «Заполнить пример» подставляет карточку для первого прогона.

Лимит на проживание по умолчанию равен половине бюджета группы. Его можно изменить в пожеланиях, например «На отель до 50 000 ₽ за поездку». Подбор просматривает до четырёх страниц Russhotels по 20 записей и заполняет очередь максимум из восьми подходящих отелей. Веб-проверки идут параллельно для трёх отелей, а запросы к модели идут последовательно. Браузер показывает по одному отелю и месту, как только они доступны. Отель можно пропустить, а места добавлять до нажатия «Достаточно мест».

Название номера, питание, цена и время заселения показываются по данным поставщика. При пожелании о включённом завтраке проверяется питание у того же тарифа, из которого взята цена. Такой тариф покрывает утра после ночёвок. Geoapify может указать бесплатность или платность, а точная сумма бывает доступна в исходных тегах. Для музеев с неизвестной ценой показывается справочная оценка Росстата, если ставка есть. В бюджете раскрываются цены за приём пищи, число платных дней, расходы на выбранные места и источники. Если сумма выходит за бюджет, автоматически сокращаются только прочие расходы.

Для выгрузки модели нажми «Остановить стенд» или `Ctrl+C` в окне запуска. Если идёт запрос, стенд завершит текущий шаг и затем выгрузит свою модель. Закрытие вкладки оставляет сервер запущенным. После принудительного завершения процесса у модели есть таймер выгрузки через два часа без запросов. Для ручного запуска без открытия браузера добавь `--no-browser`, для другого порта стенда — `--port 8766`.

### Запуск отдельных сценариев

Выполняйте команды PowerShell из папки эксперимента. Для отдельных сценариев подготовьте окружение и запустите сервер LM Studio.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
& ~/.lmstudio/bin/lms.exe load qwen3.5-9b --context-length 4096 --parallel 1 --gpu max --identifier tripflow-qwen3.5-9b -y
.\.venv\Scripts\python.exe -X utf8 -m unittest -v
.\.venv\Scripts\python.exe -X utf8 analyze.py --preferences "Нужен отель с рестораном. Живая музыка желательна."
.\.venv\Scripts\python.exe -X utf8 analyze.py --suite --output runs/replay.jsonl
.\.venv\Scripts\python.exe -X utf8 analyze.py --suite --filters-only --cases final-holdout.json --output runs/replay-filters.jsonl
.\.venv\Scripts\python.exe -X utf8 analyze.py --suite --cases release-holdout.json --output runs/replay-release.jsonl
```

Для длинных пожеланий можно передать UTF‑8 файл через `--input`. По умолчанию скрипт обращается к `127.0.0.1:1234`. Если включена авторизация LM Studio, токен берётся из `TRIPFLOW_LMSTUDIO_TOKEN`. Журнал сохраняет сырой ответ модели и проверку сценария. Для повторного запуска нужен новый путь журнала. Между вызовами внутри карточки есть пауза 2 секунды, между карточками — 5 секунд.

Дополнительный набор из 12 карточек доступен через `--cases holdout.json`. [Входные данные](../../../experiments/card-preferences/holdout.json).

## Что показали прогоны

В предыдущей версии прошло **4 из 8** [сценариев](../../../experiments/card-preferences/cases.json), включая пустой ввод. В промежуточной серии со строгими состояниями фильтров и выбором фрагментов расходов совпали **8 из 8 наборов фильтров** и **7 из 8 полных ответов**. Полная проверка сравнивает также дополнительные условия и заметки, включая суммы и их единицы в заданных сценариях. Грамматику, смысл всех подписей и достоверность источников она полностью не оценивает.

В старых ответах вегетарианство и обед в столовой попадали в требования к отелю, а транспорт и суммы иногда исчезали из расходных заметок. Цитаты помогают выявить неподдержанный фильтр, но модель всё ещё может сослаться на верный фрагмент и ошибиться в строгости или отрицании. Веса модели не менялись. Использованы примеры в промптах, структура ответа, проверки и повторная классификация неоднозначных фильтров.

| Серия Qwen3.5‑9B | Точные фильтры | Полные ответы |
|---|---:|---:|
| Первый независимый прогон десяти карточек | 7/10 | 6/10 |
| Повтор после исправления известных ошибок | 10/10 | 9/10 |
| Новые десять карточек, первый прогон | 10/10 | 8/10 |
| Целевой повтор двух карточек с исправлениями расходов | 2/2 | 2/2 |

В повторе модель пропустила дополнительное пожелание заселиться в семь утра. Медиана суммарного времени HTTP на карточку составила 3,76 с, максимум 7,32 с, без пауз между запросами. В промежуточной попытке сервер сообщал, что модель выгружена. Такой сбой помечается как инфраструктурный и теперь останавливает серию с сохранением частичных результатов.

Точное совпадение фильтров означает совпадение категории, строгости и признака запрета с ожидаемыми значениями. Оно не гарантирует применимость к реальному поставщику. Например, в текущей структуре «только парки» и «парки обязательно, остальное тоже можно» могут дать одинаковый обязательный фильтр. Если это должно менять выдачу, понадобится отдельный признак области поиска. Цитата с названием признака сама по себе также не доказывает правильность его трактовки.

В новом наборе два промаха касались расходов. Наличие проката в гостинице модель приняла за план передвижения, а в общей фразе про обеды и редкие поездки потеряла питание. Уточнили правило для проката и деление смешанной фразы на фрагменты, затем повторили оба запроса. Последний повтор измеряет исправление известных ошибок. Для полного разбора порог 90% на новом независимом наборе ещё не подтверждён. Все девять тестов Python прошли.

## Второй этап. Поиск и проверка источников

[stage2.py](../../../experiments/card-preferences/stage2.py) делает живой подбор. Russhotels возвращает варианты проживания, Geoapify — места по категориям из первого этапа. Лимит на проживание сравнивается с ориентиром для группы из опубликованного одноместного тарифа, числа ночей и путешественников. Цена и наличие на даты не подтверждены. Обязательные категории мест ограничивают выдачу, пожелания влияют на порядок.

[evidence.py](../../../experiments/card-preferences/evidence.py) находит кандидатов через веб-поиск DDGS и сверяет сайт с названием, городом и адресом отеля. Затем ищет релевантные ссылки и фрагменты на выбранном домене. Модель получает до трёх выдержек и возвращает yes, no или unclear с ID доказательства. Python подставляет исходный текст, ссылку и номер страницы PDF. Обязательное условие проходит только при confirmed. Если текст недоступен или сведений мало, результат unknown.

[source_reader.py](../../../experiments/card-preferences/source_reader.py) читает статический HTML, при необходимости запускает Playwright в отдельном браузерном контексте, извлекает текст из PDF и применяет Tesseract к первым четырём страницам без пригодного текстового слоя. За один документ читаются максимум 30 страниц, лимит загрузки 8 МБ. Поддерживаются общедоступные HTTPS-источники. Сайты с авторизацией, проверки доступа и отсутствующие сведения могут оставаться недоступными.

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -X utf8 stage2.py --card demo-card.json --output runs/card-replay.json
.\.venv\Scripts\python.exe -X utf8 stage2.py --judge-suite --cases discovery-cases.json --output runs/discovery-replay.json
```

Для поиска мест нужен GEOAPIFY_API_KEY в окружении. Файлы вывода должны быть новыми. Playwright выбирает установленный Edge на этой машине. На другой машине можно установить Chromium командой `.\.venv\Scripts\python.exe -m playwright install chromium` или выбрать канал через TRIPFLOW_BROWSER_CHANNEL. Для OCR нужен Tesseract и языковой файл rus.traineddata. Его можно положить в `.venv/tessdata` или указать каталог через TRIPFLOW_TESSDATA. Движок DDGS задаёт TRIPFLOW_SEARCH_BACKEND, по умолчанию yandex,seznam. Старую контрольную серию с ручным реестром можно повторить через `--judge-suite --registry`.

Для проверки одного произвольного отеля создайте JSON с полями `hotel` (id, name, city, address), `question`, `terms` и, при необходимости, `dates`. Структура видна в [discovery-cases.json](../../../experiments/card-preferences/discovery-cases.json). Передайте файл через `stage2.py --check input.json --output runs/check.json`. Если у известного отеля поисковая выдача не даёт подтверждённого домена из реестра, скрипт добавляет проверенные ранее страницы и ставит `registryFallback: true`. Для нового отеля результат зависит от поискового индекса и совпадения адреса.

### Исходные результаты с ручным реестром

- **Доступность текста — 9 из 11 URL.** Главная «Славянки» и её PDF по прямому HTTP-запросу вернули слишком короткий HTML. Для вопроса о времени заселения модель не получила выдержек.
- **Извлечение — 6 из 8 решающих фрагментов с эталонной страницы.** Ограничение по весу питомца для случая с кошкой было найдено в официальном анонсе того же сайта. Два вопроса с ожидаемым unknown исключены из знаменателя.
- **Судья — 9 из 9 вопросов, дошедших до модели. Полный путь — 9 из 10.** Эталон задан вручную по страницам. В ранних итерациях модель инвертировала ответы про завтрак и закрытое спа и вставляла многоточие в цитату. В финале Python подставляет выдержку целиком, а модель отвечает «да», «нет» или «неясно». Промпт уточнялся по этой контрольной серии. Качество на новых сайтах по ней не измерено.

[Контрольные вопросы](../../../experiments/card-preferences/judge-cases.json).

На живой карточке в пределах лимита нашлось семь отелей, у первых четырёх проверены условия. Выдача содержит один отель с подтверждённым рестораном и пять музеев. У «Золотого кольца» нашлось опубликованное расписание музыки. Модель сочла его подтверждением на даты поездки, Python понизил вывод до unknown из-за отсутствия конкретной даты. Для «Гостиного дома» Python также понизил contradicted до unknown: описание доставки из ближайшего ресторана само по себе не доказывает отсутствия собственного ресторана. Эти проверки покрывают явные случаи из данного эксперимента. Все 15 тестов Python прошли.

### Автоматический поиск, JavaScript и PDF

В серии с автопоиском верны 5 из 7 итоговых вердиктов. «Акварель» отсутствовала в реестре. Система нашла её сайт и подтвердила своё прочтение по опубликованным условиям парковки и часам завтрака. Для «Золотого кольца» модель получила выдержку со страницы 2 скана правил и верно ответила на вопрос о времени выезда. Для «Славянки» дважды выбраны фрагменты про заселение детей вместо нужных правил заезда. При целевом повторе с закреплённой страницей и повышенным приоритетом фрагментов со временем или наличием номеров оба ответа совпали с эталоном. Этот повтор проверяет извлечение и модель, а не повторный успех веб-поиска.

В ранней серии автоматически найденные страницы дали 4 из 7 вердиктов. Поисковый индекс иногда возвращал пустую выдачу и ссылку на общий сайт сети. Ошибки поиска, загрузки и отсечения ответа LM Studio фиксируются отдельно. На одном полном прогоне карточки Geoapify вернул пять музеев, но поиск не подтвердил обязательный ресторан ни у одного проверенного отеля. Этот журнал предшествует добавлению резерва по известным доменам. Все 17 тестов Python прошли, после прогонов Qwen выгружена.

## Третий этап. Дополнительные расходы по выбранной карточке

[stage3.py](../../../experiments/card-preferences/stage3.py) получает даты, число путешественников, выбранный отель, места и четыре заметки из результата первого этапа. Qwen предлагает стоимость питания по приёмам пищи, городского транспорта, прочих трат и резерва. Для питания, транспорта и развлечений харнес подгружает локальные ставки Росстата. В результате он сохраняет исходный период и область применимости использованных ставок. Резерв, а также прочие траты без применимой ставки, оцениваются по явно описанному допущению.

Модель оценивает питание и транспорт для одного человека на типичный день, прочие траты на человека за поездку, резерв на группу за поездку. Python применяет включения, приводит суммы к рублям на всю группу и складывает четыре категории. Отдельно введённая сумма с единицей берётся из `fixedExpenses`. Уже оценённые посещения передаются модели как исключения для прочих трат. Цена проживания и билетов обрабатывается за пределами этого расчёта.

С флагом `--verify-tariff` харнес запускает второй этап для поиска завтрака по точному названию выбранного тарифа. Подтверждённый завтрак покрывает утра после ночёвок. Условия обеда, ужина и городского шаттла можно передать как готовые факты с источником и количеством покрытых дней. Шаттл обнуляет расходы только на дни, когда он покрывает все запланированные поездки. Трансфер из аэропорта городские расходы не уменьшает. Автоматический поиск маршрутов шаттлов и условий питания в выбранных местах в этой версии отсутствует.

```powershell
.\.venv\Scripts\python.exe -X utf8 stage3.py --suite budget-cases.json --output runs/budget-replay.jsonl
.\.venv\Scripts\python.exe -X utf8 stage3.py --card budget-demo.json --verify-tariff --output runs/budget-tariff-replay.jsonl
& ~/.lmstudio/bin/lms.exe unload tripflow-qwen3.5-9b
```

Формат входа показан в [примере карточки](../../../experiments/card-preferences/budget-demo.json). Требуется загруженная Qwen в LM Studio. Для проверки тарифа используются зависимости второго этапа. Вывод создаётся по новому пути и содержит суммы, применённые включения, допущения, ставки и ответы модели. Запросы выполняются последовательно с паузами.

### Результаты прогона Qwen3.5-9B

В первом прогоне прошли 17 из 24 проверок диапазонов. Модель путала цену за день с ценой за поездку. Когда длительность поездки убрали из запросов с дневными ставками и уточнили справочные ориентиры, промежуточный прогон дал 22 из 24. Модель повторно начислила включённый завтрак и завысила стоимость ресторанного ужина. В последней версии модель оценивает отдельные приёмы пищи, а Python применяет включения по дням.

В финальном прогоне прошли все 24 проверки на шести [контрольных карточках](../../../experiments/card-preferences/budget-cases.json). Суммы в рублях на двух путешественников на три дня.

| Карточка | Питание | Транспорт | Прочее | Резерв |
|---|---:|---:|---:|---:|
| Без подтверждённых включений | 8 676 | 954 | 0 | 15 000 |

## Сквозная проверка трёх этапов

Контрольные входы для [пожеланий](../../../experiments/card-preferences/audit-preferences.json), [судьи](../../../experiments/card-preferences/audit-judge-cases.json) и [бюджета](../../../experiments/card-preferences/audit-budget.json) проверяют разные причины ошибок. Результат поиска оценивается отдельно от результата судьи на тех же сохранённых выдержках. Тестовая карточка для сквозного прогона использует Russhotels и Geoapify и выбирает первые подходящие отель и место, имитируя выбор пользователя. Тариф на даты и цены билетов этим прогоном не подтверждаются.

```powershell
.\.venv\Scripts\python.exe -X utf8 -m unittest
.\.venv\Scripts\python.exe -X utf8 analyze.py --suite --cases audit-preferences.json --output runs/audit-preferences-replay.jsonl
.\.venv\Scripts\python.exe -X utf8 analyze.py --suite --cases audit-holdout.json --output runs/audit-holdout-replay.jsonl
.\.venv\Scripts\python.exe -X utf8 stage2.py --judge-suite --cases discovery-cases.json --output runs/audit-discovery-replay.json
.\.venv\Scripts\python.exe -X utf8 stage2.py --snapshot audit-judge-cases.json --output runs/audit-judge-replay.json
.\.venv\Scripts\python.exe -X utf8 stage3.py --suite audit-budget.json --output runs/audit-budget-replay.jsonl
.\.venv\Scripts\python.exe -X utf8 stage3.py --suite audit-budget-holdout.json --output runs/audit-budget-holdout-replay.jsonl
.\.venv\Scripts\python.exe -X utf8 audit_pipeline.py --card audit-card.json --output runs/audit-pipeline-replay.json
```

Поиск хранит число кандидатов, до которых не дошла проверка, и время получения выдержек. Судья возвращает выделенную дословную цитату. Код проверяет её в исходном тексте. Когда одновременно есть календарь расходов и календарь включений, из оценки вычитаются только совпадающие дни. Лимит из пожеланий сохраняется рядом со справочной оценкой как отдельная величина, поэтому видно превышение.

В сквозном прогоне Russhotels дал семь вариантов с пригодной ориентировочной ценой. Из первых четырёх система выбрала «Золотое кольцо», а Geoapify вернул Музей истории ВДНХ. Дополнительные расходы составили 18 130 ₽, включая 8 676 ₽ на питание, 954 ₽ на транспорт, 2 500 ₽ на сувениры и 6 000 ₽ резерва. Подбор занял 151,86 с, расчёт расходов — 11,05 с. В живой серии проверки гостиничных условий поиск и чтение выдержек занимали 5,35–31,66 с на вопрос, запрос судьи — 1,89–3,16 с. У одного ответа решающая выдержка пришла из PDF, хотя эталонный маркер был задан для HTML-страницы. Все семь вердиктов совпали с ожиданиями.

| Проверка | Результат |
|---|---|
| Пожелания, 10 карточек | Первый прогон — 6/10 наборов фильтров, 5/10 полных ответов. Повтор — 10/10 и 9/10. |
| Пожелания, пять новых карточек | Первый прогон — 4/5 наборов фильтров, 3/5 полных ответов. Найдены парковка вне отеля и потеря суммы на театр рядом с резервом. |
| Бюджет, восемь карточек | Первый прогон — 5/8 полных карточек. После поправок и целевого повтора двух карточек все восемь прошли. Эталон для лимита на питание дополнен проверкой суммы лимита и превышения. Верхняя граница для театра сверена с локальной ставкой 3 031,53 ₽ за билет. |
| Бюджет, три новые карточки | 12/12 проверок категорий. |
| Судья, шесть спорных выдержек | Первый прогон — 5/6. Модель приняла условие другого тарифа за опровержение выбранного. После проверки, что дословная цитата связывает названный тариф с условием, повтор дал 6/6. |

В смешанной поездке модель оценила питание по расписанию в 36 162 ₽ вместо 108 495 ₽ в первом прогоне. Два проезда на метро за поездку для трёх человек после смены единицы дали 477 ₽. В случае с дневным лимитом расчёт показал оценку 17 352 ₽, лимит 10 800 ₽ и превышение 6 552 ₽. Покупку по более низкой цене этот расчёт не подтверждает.

При повторной проверке тарифа судья сначала предложил отрицательный вердикт по общей странице питания, но проверка цитаты вернула `unknown`. Сумма питания сохранилась целиком. Если модель пишет в статусной подписи о желательности или обязательности вместо наличия услуги, харнес подставляет нейтральную подпись к названию условия.

В целевых повторах модель сохранила и музыку по пятницам, и требование к завтраку. В повторе двух новых карточек фильтр парковки вне отеля исчез, но модель ещё теряла сумму на театр. После добавления проверки денежного фрагмента воспроизведение сохранённых ответов подтвердило, что код сохраняет обе суммы и заменяет ошибочные статусные подписи. Эти повторы проверяют исправления известных случаев.

В повторном сквозном прогоне получены четыре отеля, пять музеев и 18 124 ₽ дополнительных расходов. Из 169,77 с подбора на разбор пожеланий ушло 32,54 с, получение кандидатов заняло 1,21 с, проверка отелей — 135,68 с. Последующий бюджет занял 10,63 с. У «Славянки» модель указала `contradicted` по выезду до 15:00, хотя опубликованные правила подтверждали лишь возможность позднего выезда без конкретного часа. После прогона добавлена проверка, которая в таком случае возвращает `unknown`. Её покрывает один из 43 прошедших тестов Python.
