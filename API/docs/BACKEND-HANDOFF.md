# TripFlow. Интеграция C# backend с Python

Договорённость от 22 ноября 2026 года. React опрашивает C# через `GET {card}` во время подбора и расчёта сметы. Python обрабатывает принятый запрос в фоне без отдельной очереди задач и отправляет в C# один итоговый callback на задачу. Все варианты текущего подбора передаются одним пакетом и становятся доступны React одновременно. [Контракт Python](CONTRACT.md) · [Сценарии](SCENARIOS.md)

Подбор и расчёт сметы остаются отдельными операциями. Основной рассматриваемый вариант для инференса — прямой вызов DeepSeek с сервера Python. LM Studio рассматривается как дополнительный режим. Способ поиска и источники цен ещё выбираются. URL, поля и JSON ниже служат рабочими примерами для согласования. [Архитектура](ARCHITECTURE.md#подбор-и-расчёт-бюджета) · [Стенды](RESEARCH.md#модель-и-стенды-карточки)

## Сценарий от черновика до сметы

~~~mermaid
sequenceDiagram
    participant R as React
    participant C as C# backend
    participant P as Python API
    R->>C: POST {card}/generation с сохранёнными параметрами
    C->>C: Сохранить taskId и версию карточки
    C->>P: POST /v1/recommendations
    P-->>C: 202 Accepted
    C-->>R: 202 Accepted с текущим статусом запрошенных типов
    par Доставка результата
        P->>C: Callback recommendations.finished со всей выдачей
        C->>C: Сохранить пакет и итоговые статусы
        C-->>P: Подтверждение после записи
    and Получение статуса в React
        loop Пока экран открыт и запрошенный подбор pending
            R->>C: GET {card}
            C-->>R: Сохранённый статус и пакет после завершения
        end
    end
    opt Пользователю нужны дополнительные варианты
        R->>C: POST {card}/generation для нужного типа
        Note over R,P: Та же схема с новым taskId и актуальными исключениями
    end
    R->>C: Сохранить выбранный отель и места
    R->>C: POST {card}/budget
    C->>C: Сохранить taskId, версию карточки и выбор
    C->>P: POST /v1/budget с актуальным выбором
    P-->>C: 202 Accepted
    C-->>R: 202 Accepted с текущим статусом сметы
    par Доставка результата
        P->>C: Callback budget.finished
        C->>C: Сохранить смету или ошибку для задачи
        C-->>P: Подтверждение после записи
    and Получение статуса в React
        loop Пока экран открыт и последний статус pending
            R->>C: GET {card}
            C-->>R: Сохранённый статус и результат или ошибка, если есть
        end
    end
~~~

Python получает данные, проверяет кандидатов и доставляет готовый результат. C# хранит карточку, её версию, выбор автора, исключения, полученные списки вариантов и итоговый бюджет. React получает всё состояние карточки через C#.

## Три маршрута межсервисного обмена

| Метод и рабочий путь | Направление | Назначение |
|---|---|---|
| `POST /v1/recommendations` | C# → Python | Первый подбор и догенерация. Можно запросить отели, места или оба типа. |
| `POST /v1/budget` | C# → Python | Оценка питания, городского транспорта, прочих расходов и резерва по актуальному выбору. |
| `POST /internal/tripflow/events` | Python → C# | Один настроенный HTTPS-адрес для итоговых callback подбора и сметы. Путь приведён как предложение. |

Обе операции Python возвращают `202 Accepted` после принятия и сохранения задачи для фонового выполнения. Входящие запросы C# и обратная доставка используют отдельные ключи. C# настраивает адрес приёма callback. Для запросов с JSON предлагается `Content-Type: application/json`, для ключей — заголовки `X-API-Key` на стороне Python и `X-Callback-Key` на стороне C#. Для принятого callback предлагается `204 No Content`.

Рабочий пример тела `202` — `{"taskId":"rec-001","status":"accepted"}`. Статус готовности подбора и сметы меняется после соответствующих callback.

### Общие правила типов

Далее используются типы JSON Schema. **Обязательное** поле должно присутствовать. `null` допустим там, где он явно указан в столбце типа. Пустой список передаётся как `[]`. Python приводит пустые и пробельные входные nullable-строки к `null`. Для необязательных полей смысл отсутствия указан в описании. Имена полей в новых структурах приведены в `camelCase`. Точные поля и ограничения для межсервисного обмена предложены для согласования.

#### TripContext

Общий объект `trip` в запросах к Python.

| Поле | Тип | Присутствие | Смысл и ограничения |
|---|---|---|---|
| `destinationId` | `string` | Обязательно | ID из общего справочника направлений, например `ru-moscow`. |
| `startDate` | `string` | Обязательно | Календарная дата в формате `YYYY-MM-DD`. |
| `endDate` | `string` | Обязательно | Календарная дата в том же формате, не раньше `startDate`. Ночи — разница дат. |
| `travelers` | `integer` | Обязательно | Положительное число путешественников. |
| `budgetRub` | `integer` | Обязательно | Положительная сумма в рублях на всю группу и всю поездку, включая резерв. |
| `preferences` | `string`, `null` | Обязательно | Текст пожеланий. `null` означает, что пожелания отсутствуют. |

#### Coordinates

`Coordinates` — объект с двумя обязательными полями `latitude` и `longitude` типа `number`. Широта допускает значения от −90 до 90, долгота — от −180 до 180.

#### Цена отеля

`price` у отеля — одно число в рублях за **всю группу и всё проживание на даты поездки**. Если источник даёт цену за ночь, номер или человека, Python приводит её к сумме на группу до отправки варианта. Если доступна лишь цена «от» и обоснованную оценку полной стоимости получить не удалось, передаётся `null`. Python хранит основание суммы у себя. C# сравнивает `price` с лимитом на отель и добавляет её в смету как ориентировочную стоимость проживания. [Единицы и ограничения цен в стенде](research/deepseek-web-trip/report.md#flash-с-веб-поиском)

| Поле | Тип | Присутствие | Смысл и ограничения |
|---|---|---|---|
| `price` | `integer`, `null` | Обязательно | Неотрицательная сумма в целых рублях за всю группу и все ночи. `null` означает неизвестную стоимость. |

#### AdmissionPriceQuote

| Поле `AdmissionPriceQuote` | Тип | Присутствие | Смысл и ограничения |
|---|---|---|---|
| `amountRub` | `integer` | Обязательно | Сумма в целых рублях для указанной единицы цены, неотрицательная. `0` используется для подтверждённой бесплатности. |
| `basis` | `string` | Обязательно | `person_admission` — одно посещение на человека, `group_admission` — одно посещение на группу. |
| `kind` | `string` | Обязательно | `source` — цена из источника, `estimate` — расчётная оценка. |
| `isFromPrice` | `boolean` | Необязательно | `true` для цены «от». При отсутствии поля используется `false`. |
| `sourceUrl` | `string`, `null` | Необязательно | HTTPS-ссылка на основание цены. Для цены из источника ссылка указывается здесь или находится в связанной записи объекта либо тарифа. |

Неизвестная цена посещения передаётся как `price: null`.

#### TaskAccepted и ошибки

| Объект | Поле | Тип | Присутствие и смысл |
|---|---|---|---|
| `TaskAccepted` | `taskId` | `string` | Обязательно. ID задачи из запроса C#. |
| `TaskAccepted` | `status` | `string` | Обязательно. Значение `accepted`. |
| `ErrorResponse` | `taskId` | `string`, `null` | Обязательно. ID задачи, если его удалось прочитать из отклонённого запроса. |
| `ErrorResponse` | `error` | `object` (`ErrorDetail`) | Обязательно. Ошибка до принятия задачи. |
| `ErrorDetail` | `code` | `string` | Обязательно. Машинный код. Каталог кодов согласуется отдельно. |
| `ErrorDetail` | `message` | `string` | Обязательно. Краткое описание причины. |
| `ErrorDetail` | `fields` | `object` | Необязательно. Ключи — пути вроде `trip.endDate`, значения — непустые массивы `string` с ошибками полей. |

Если Python отклоняет запрос до `202`, предлагается вернуть HTTP-ошибку с `ErrorResponse`. Сбой принятой задачи сообщается в итоговом callback с `error` в ответе сметы или в результате затронутого типа подбора.

### 1. Запрос рекомендаций

Пример для первичного подбора. C# отправляет параметры поездки и на каждый нужный тип задаёт число вариантов и доступный лимит, если он уже известен. Поле `maxTotalRub` в примере означает сумму на всю группу за все ночи для отеля и на одно групповое посещение для места. Для догенерации C# вызывает тот же маршрут с новым `taskId`, запрашивает только нужный тип и передаёт уточнение и исключения. При замене отеля или места C# высвобождает его стоимость при расчёте нового лимита. [Правила подбора](ARCHITECTURE.md#подбор-и-расчёт-бюджета)

| Поле `RecommendationsRequest` | Тип | Присутствие | Смысл и ограничения |
|---|---|---|---|
| `taskId` | `string` | Обязательно | Уникальный непустой ID, который создаёт C#. |
| `trip` | `object` (`TripContext`) | Обязательно | Актуальные параметры карточки. |
| `targets` | `object` | Обязательно | Как минимум один из ключей `hotels` и `attractions`. |
| `targets.hotels`, `targets.attractions` | `object` (`RecommendationTarget`) | Необязательны по отдельности | Если ключ отсутствует, подбор этого типа не запускается. |
| `RecommendationTarget.count` | `integer` | Обязательно | Положительное максимальное число вариантов для этого типа. |
| `RecommendationTarget.maxTotalRub` | `integer`, `null` | Обязательно | Неотрицательный лимит на один подходящий вариант в указанных выше единицах. `null` означает, что отдельный лимит ещё не задан. |
| `RecommendationTarget.refinement` | `string`, `null` | Необязательно | Дополнительное пожелание только для этого типа. Отсутствие или `null` означает подбор по общим пожеланиям. |
| `RecommendationTarget.excludedObjectIds` | `array` из `string` | Необязательно | Уникальные `objectId`, которые нужно исключить из выдачи. Отсутствие равнозначно пустому массиву. |

~~~json
{
  "taskId": "rec-001",
  "trip": {
    "destinationId": "ru-moscow",
    "startDate": "2027-06-10",
    "endDate": "2027-06-15",
    "travelers": 2,
    "budgetRub": 60000,
    "preferences": "Отель рядом с метро, музеи и прогулки"
  },
  "targets": {
    "hotels": { "count": 1, "maxTotalRub": 30000 },
    "attractions": { "count": 4, "maxTotalRub": null }
  }
}
~~~

При запросе дополнительных отелей с теми же параметрами поездки блок `targets` может выглядеть так. В исключения входят все уже полученные и отклонённые объекты этого типа.

~~~json
{
  "hotels": {
    "count": 2,
    "maxTotalRub": 30000,
    "refinement": "Можно дальше от центра",
    "excludedObjectIds": ["hotel-boulevard"]
  }
}
~~~

### 2. Итоговый callback подбора

Когда завершён поиск всех запрошенных типов, Python отправляет один `recommendations.finished` с полным пакетом найденных вариантов и результатом по каждому типу. C# сохраняет пакет и обновляет статусы вместе, чтобы один `GET {card}` вернул всю новую выдачу. `objectId` — стабильный ID объекта в каталоге TripFlow. C# связывает вариант и его цену с конкретной карточкой. [Идентификация объектов](ARCHITECTURE.md#постоянный-каталог-объектов)

| Общее поле callback | Тип | Присутствие | Смысл и ограничения |
|---|---|---|---|
| `taskId` | `string` | Обязательно | ID принятой задачи. |
| `event` | `string` | Обязательно | Рабочие имена `recommendations.finished` и `budget.finished`. Значение определяет остальные поля. |

| Поле результата подбора | Тип | Присутствие | Смысл и ограничения |
|---|---|---|---|
| `results` | `object` | Обязательно в `recommendations.finished` | Содержит ровно запрошенные ключи `hotels` и/или `attractions`, каждый со значением `RecommendationResult`. |
| `RecommendationResult.status` | `string` | Обязательно | `succeeded` — поиск завершён, включая пустую выдачу. `partial` — поиск прервался, но есть пригодные варианты. `failed` — поиск завершился с ошибкой и без пригодных вариантов. |
| `RecommendationResult.items` | `array` из `Candidate` | Обязательно | Все варианты этого типа, найденные за текущий запрос, в порядке подбора и в пределах запрошенного `count`. Пустая выдача и `failed` передаются как `[]`. |
| `RecommendationResult.hasMore` | `boolean`, `null` | Обязательно | `true` — найден следующий пригодный вариант за пределами пакета. `false` — поиск исчерпан. `null` — наличие следующих вариантов неизвестно, в том числе при `failed`. |
| `RecommendationResult.error` | `object` (`ErrorDetail`) | При `failed` обязательно, при `partial` необязательно | Причина сбоя или неполного поиска. |

#### Candidate

| Поле | Тип | Присутствие | Смысл и ограничения |
|---|---|---|---|
| `objectId` | `string` | Обязательно | Стабильный ID объекта из каталога Python. |
| `name` | `string` | Обязательно | Название подтверждённого отеля или места. |
| `address` | `string`, `null` | Обязательно | Адрес, если известен. |
| `coordinates` | `object` (`Coordinates`), `null` | Обязательно | Координаты, если установлены. |
| `imageUrl` | `string`, `null` | Обязательно | HTTPS-ссылка на изображение, если доступно. |
| `sourceUrl` | `string` | Обязательно | HTTPS-ссылка на источник сведений об объекте. |
| `price` | `integer`, `null` для отеля. `object` (`AdmissionPriceQuote`), `null` для места | Обязательно | Отель — сумма за всё проживание группы. Место — цена одного посещения с указанием единицы. |
| `description` | `string`, `null` | Необязательно | Краткое описание на основе источников. |
| `recommendationReason` | `string`, `null` | Необязательно | Краткое объяснение, почему вариант подходит под пожелания. |
| `stars` | `integer`, `null` | Необязательно для отеля | Звёздность от 1 до 5, если подтверждена. |
| `category` | `string`, `null` | Необязательно для места | Категория, например «Музей». |
| `tariff` | `object` (`TariffSnapshot`), `null` | Необязательно для отеля | Данные конкретного тарифа, если найдены. |

У достопримечательности в `results.attractions.items` всегда присутствуют `imageUrl`, `coordinates` и `address`. Каждое из этих полей может иметь значение `null`, если у источников нет подтверждённых сведений.

~~~json
{
  "taskId": "rec-001",
  "event": "recommendations.finished",
  "results": {
    "hotels": {
      "status": "succeeded",
      "items": [
        {
          "objectId": "hotel-boulevard",
          "name": "Бульварный дом",
          "address": null,
          "coordinates": { "latitude": 55.765, "longitude": 37.638 },
          "imageUrl": null,
          "sourceUrl": "https://example.org/hotels/boulevard",
          "price": 27000
        }
      ],
      "hasMore": true
    },
    "attractions": {
      "status": "succeeded",
      "items": [
        {
          "objectId": "place-museum",
          "name": "Городской музей",
          "category": "Музей",
          "imageUrl": "https://example.org/images/city-museum.jpg",
          "coordinates": { "latitude": 55.741, "longitude": 37.62 },
          "address": "Москва, Музейная улица, 10",
          "sourceUrl": "https://example.org/places/city-museum",
          "price": { "amountRub": 900, "basis": "person_admission", "kind": "estimate" }
        }
      ],
      "hasMore": false
    }
  }
}
~~~

В примере поиск завершился по обоим типам. Для отелей доступна догенерация, а для мест подходящие кандидаты исчерпаны. Если поиск отелей завершится ошибкой, результат `hotels` получит `status: "failed"`, `items: []`, `hasMore: null` и `error`. Пригодные варианты мест всё равно входят в тот же callback.

### 3. Запрос бюджета после выбора

C# фиксирует версию карточки и отправляет в Python параметры поездки, выбранный отель с конкретным тарифом и включёнными услугами, выбранные места и имеющиеся цены. Подтверждение завтрака должно относиться к тарифу или нужным дням. Сведения общего уровня об отеле сами по себе не дают оснований вычитать завтрак из сметы. [Правила бюджета](ARCHITECTURE.md#подбор-и-расчёт-бюджета) · [Пример проверки тарифа](research/deepseek-flash/README.md#отдельные-этапы)

| Поле `BudgetRequest` | Тип | Присутствие | Смысл и ограничения |
|---|---|---|---|
| `taskId` | `string` | Обязательно | ID новой задачи расчёта. |
| `trip` | `object` (`TripContext`) | Обязательно | Снимок исходных параметров. |
| `selectedHotel` | `object` (`SelectedHotel`), `null` | Обязательно | Выбранный отель. `null` означает, что отель в расчёт не передан. |
| `selectedAttractions` | `array` из `SelectedAttraction` | Обязательно | Выбранные посещения. Пустой массив означает план без посещений. |

| Объект | Поле | Тип | Присутствие и смысл |
|---|---|---|---|
| `SelectedHotel` | `objectId` | `string` | Обязательно. ID отеля из каталога. |
| `SelectedHotel` | `price` | `integer`, `null` | Обязательно. Сохранённая сумма выбранного варианта за всю группу и все ночи. |
| `SelectedHotel` | `tariff` | `object` (`TariffSnapshot`) | Обязательно. Сведения о выбранном тарифе и включённых услугах. |
| `TariffSnapshot` | `name` | `string`, `null` | Обязательно. Название тарифа, если известно. |
| `TariffSnapshot` | `includedServices` | `array` из `IncludedService` | Обязательно. Услуги, проверенные для тарифа. Пустой список допустим. |
| `IncludedService` | `service` | `string` | Обязательно. Ключ услуги. В примере `breakfast`. |
| `IncludedService` | `status` | `string` | Обязательно. `confirmed`, `contradicted` или `unknown`. Смету уменьшает только подтверждённое включение. |
| `IncludedService` | `dates` | `array` из `string`, `null` | Обязательно. Даты в формате `YYYY-MM-DD`. Для `confirmed` значение `null` означает подтверждение на весь соответствующий период тарифа. |
| `IncludedService` | `sourceUrl` | `string`, `null` | Обязательно. HTTPS-ссылка на подтверждение тарифа, обязательное ненулевое значение для `confirmed`. |
| `SelectedAttraction` | `objectId` | `string` | Обязательно. ID места из каталога. |

### 4. Итоговый callback бюджета

Рабочее имя события в примере — `budget.finished`. Python возвращает дополнительные расходы на всю группу за поездку. C# суммирует их с проживанием и билетами по тому выбору, к которому привязана задача. В примере итог **54 000 ₽** получается из **27 000 ₽** за отель, **1 800 ₽** за два билета и **25 200 ₽** дополнительных расходов. Остаток — **6 000 ₽**. Если у выбранного места цена неизвестна, C# показывает известную сумму и помечает смету как неполную. [Смета и версия карточки](ARCHITECTURE.md#подбор-и-расчёт-бюджета)

| Дополнительное поле `budget.finished` | Тип | Присутствие | Смысл и ограничения |
|---|---|---|---|
| `status` | `string` | Обязательно | `succeeded` или `failed`. Успешная оценка дополнительных расходов допускает неполную итоговую смету C#, если отсутствуют цены выбранных объектов. |
| `expenses` | `object` (`Expenses`), `null` | Обязательно | При `succeeded` передаётся объект, при `failed` — `null`. |
| `error` | `object` (`ErrorDetail`) | Обязательно при `failed` | Причина сбоя. |

Все поля `Expenses` обязательны. Суммы — неотрицательные целые рубли на всю группу и поездку.

| Поле `Expenses` | Тип | Смысл |
|---|---|---|
| `foodTotalRub` | `integer` | Питание с учётом подтверждённых включений тарифа. |
| `localTransportTotalRub` | `integer` | Городской транспорт. |
| `otherExpensesTotalRub` | `integer` | Прочие траты, исключая уже учтённые статьи. |
| `reserveTotalRub` | `integer` | Резерв на поездку. |

~~~json
{
  "taskId": "budget-001",
  "event": "budget.finished",
  "status": "succeeded",
  "expenses": {
    "foodTotalRub": 14400,
    "localTransportTotalRub": 4800,
    "otherExpensesTotalRub": 0,
    "reserveTotalRub": 6000
  }
}
~~~

Пример завершившейся с ошибкой бюджетной задачи. Код в примере условный.

~~~json
{
  "taskId": "budget-002",
  "event": "budget.finished",
  "status": "failed",
  "expenses": null,
  "error": { "code": "BUDGET_ESTIMATE_FAILED", "message": "Не удалось рассчитать дополнительные расходы" }
}
~~~

## Версии и повторы

1. C# до отправки связывает `taskId` с версией карточки и снимком входных данных. Для сметы снимок включает выбранный отель, тариф и места.
2. Python сохраняет один итог по `taskId` перед отправкой. При временном сбое доставки повторяет тот же callback с тем же `taskId` и тем же телом.
3. C# применяет пакет и фиксирует приём в одной транзакции, затем подтверждает доставку. Повтор по тому же `taskId` подтверждается без повторного применения. Запоздалый callback по устаревшей версии карточки, заменённой или просроченной задаче подтверждается после фиксации приёма и не меняет актуальные данные.
4. Повтор запроса с тем же `taskId` и теми же данными возвращает прежнее подтверждение приёма. Для нового подбора, догенерации или пересчёта C# создаёт новый `taskId`.

На стороне C# для принятой задачи нужен предельный срок ожидания. Если итог не поступил, текущая попытка переходит в `failed`, чтобы React завершил polling и мог предложить повтор. Точные сроки и интервалы повторной доставки согласуются при реализации.

## Контракты React → C#

`{dashboard}` означает `/api/dashboards/{dashboardId}`, `{card}` — `{dashboard}/cards/{cardId}`. Оба параметра пути — строки в формате UUID. В маршрутах текущего backend используются существующие DTO. Поля для подбора и бюджета ниже — предлагаемые расширения. [Маршруты карточек](../../Backend/Dashboards.cs#L22) · [Состояние backend](../../Backend/README.md#проверка-через-swagger)

| Маршрут | Тело запроса | Успешный ответ | Состояние |
|---|---|---|---|
| `GET /api/destinations` | Без тела | `200`, `array` из `DestinationView` | Есть |
| `POST {dashboard}/cards` | `TripInput` | `201`, `TripCardView` | Есть |
| `GET {card}` | Без тела | `200`, `TripCardView` | Есть, предлагается расширить ответ |
| `PUT {card}` | `TripInput` | `200`, `TripCardView` | Есть |
| `POST {card}/publish` | Без тела | `200`, `TripCardView` | Есть |
| `POST {card}/generation` | `GenerationInput` | `202`, расширенный `TripCardView` с состоянием запрошенных типов подбора | Предложение |
| `PUT {card}/hotel` | `HotelSelectionInput` | `200`, расширенный `TripCardView` | Предложение |
| `PUT {card}/attractions` | `AttractionSelectionInput` | `200`, расширенный `TripCardView` | Предложение |
| `POST {card}/budget` | Без тела. C# берёт сохранённый выбор | `202`, расширенный `TripCardView` с текущим состоянием сметы | Предложение |

Для подбора и сметы действует одна схема polling.

1. C# сохраняет `taskId`, версию карточки и снимок входных данных, отмечает запрошенные типы подбора или смету как `pending` и отправляет задачу в Python. После подтверждения приёма C# возвращает React `202 Accepted` и текущее состояние карточки. Если Python явно отклонил задачу, C# завершает попытку с ошибкой.
2. Пока экран открыт и хотя бы один нужный статус равен `pending`, React раз в несколько секунд делает короткий `GET {card}`. C# возвращает состояние из своего хранилища.
3. При `succeeded` или `partial` React показывает весь полученный список соответствующего типа. При `partial` он может дополнительно показать причину неполной выдачи. При `failed` показывает ошибку. Для сметы React показывает `budget.result` при `succeeded` и `budget.error` при `failed`.
4. React прекращает polling, когда нужные статусы вышли из `pending` или экран закрыт. При повторном открытии редактора первый `GET {card}` возвращает последнее состояние и позволяет возобновить опрос, если работа ещё идёт.

Догенерация запрашивает пакет для одного типа. Ранее сохранённые варианты остаются видны, пока идёт поиск. По завершении C# добавляет весь новый пакет разом. Если догенерация завершается ошибкой, ранее сохранённый список и выбор остаются доступны.

После редактирования параметров или выбора старая смета получает статус `stale`. Актуальный расчёт запускается через `POST {card}/budget`.

## Что ещё согласовать

- Точный формат `trip` и направления, структуру тарифа и правила подтверждения цен. Для отеля сумма уже относится ко всему проживанию группы.
