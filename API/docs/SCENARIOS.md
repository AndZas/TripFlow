# Сценарии генерации карточки TripFlow

Сценарии показывают поведение Python и целевой обмен с C# и React. Локальный мок можно проверить отдельно в Swagger. Формы запроса на Render соответствуют опубликованному релизу. [Проверка через портал](PORTAL.md#проверка-api-через-render) [Архитектура](ARCHITECTURE.md) · [Контракт Python](CONTRACT.md) · [Маршруты и JSON](BACKEND-HANDOFF.md)

## 1. Первичный подбор вариантов

| Шаг | Что происходит |
|---|---|
| Запуск | Автор сохраняет город, даты, число путешественников, бюджет и пожелания. React вызывает `POST {card}/generation`. |
| Приём | C# связывает `taskId` с версией карточки, отмечает нужные типы как `pending` и отправляет `POST /v1/recommendations` для каждого типа со своим ID. Python сохраняет задачу для фонового выполнения, подтверждает её ответом `202 Accepted` и запускает обработку без отдельной очереди. |
| Ожидание | React периодически вызывает `GET {card}` у C#. Пока задача выполняется, React показывает состояние подбора. |
| Подбор | Мок проверяет цену и исключения в тестовом каталоге Москвы и ограничивает выдачу через `count`. Интерпретация пожеланий и поиск реальных объектов относятся к следующему этапу. |
| Выдача | C# получает по GET итог одной задачи, сохраняет его и обновляет статус соответствующего списка. Следующий опрос карточки показывает готовые варианты. |

Для отелей и мест создаются отдельные задачи. Пользователь может увидеть один список, пока второй формируется. Смета запускается после выбора.

Для проверки мока задайте отелям `count: 2`, а лимит и исключения передайте как `null`. Мок вернёт два из трёх отелей и `hasMore: true`. Если исключить один отель, оставшиеся два заполнят список, а `hasMore` станет `false` при отсутствии других ограничений.

## 2. Пустой, частичный и завершённый поиск

| Что произошло по одному типу | Что получит C# в поле `result` |
|---|---|
| Запрошено 5 вариантов, найдено 6 подходящих | `succeeded`, 5 вариантов в `items`, `hasMore: true`. |
| Поиск исчерпан, найдено 2 варианта | `succeeded`, 2 варианта, `hasMore: false`. |
| Поиск исчерпан и кандидатов нет | `succeeded`, `items: []`, `hasMore: false`. |
| Часть поиска недоступна, есть 2 пригодных варианта, наличие следующих неизвестно | `partial`, 2 варианта, `hasMore: null`. |
| Поиск завершился с ошибкой без пригодных вариантов | `failed`, `items: []`, `hasMore: null` и описание ошибки. |

Результаты отелей и мест независимы. Случай `partial` описывает будущий поиск с внешними источниками. Ошибка одной задачи не влияет на выдачу второй. При `hasMore: null` пользователь может повторить поиск для нужного типа. При `hasMore: false` новый поиск имеет смысл после изменения условий.

## 3. Догенерация

Автор просит дополнительные отели, например «Можно дальше от центра». C# создаёт новый `taskId`, вызывает `POST /v1/recommendations` с `targets: "hotels"` и передаёт актуальные параметры, уточнение, лимит и ID уже полученных и отклонённых отелей. При замене текущего отеля его стоимость вычитается из удерживаемых расходов при расчёте лимита.

До завершения React показывает сохранённую выдачу и статус дополнительного поиска. После чтения результата C# добавляет новый пакет целиком в порядке из ответа. Варианты мест и текущий выбор сохраняются. При ошибке пользователь продолжает видеть предыдущий список и может повторить поиск.

## 4. Цена и лимит

| Ситуация | Как применяется цена |
|---|---|
| 27 000 ₽ за проживание всей группы, лимит 30 000 ₽ | Отель проходит проверку цены. В смету идут 27 000 ₽ за весь срок. |
| Билет по 900 ₽ на человека, путешественников двое, лимит 1 500 ₽ | Групповая цена 1 800 ₽ превышает лимит на посещение. |
| Групповой билет за 1 200 ₽ | При одном посещении в смету идут 1 200 ₽. |
| Цена достопримечательности неизвестна | `price: null`. Соответствие лимиту не подтверждено. |
| Бесплатный вход подтверждён | Указана цена `0` с соответствующим основанием. |

Общая региональная ставка и сумма конкретного объекта имеют разные основания. Уровень и период исходных справочных данных сохраняются. Положительная рублёвая дробная сумма округляется вверх. Например, 333,01 ₽ переходят в 334 ₽.

## 5. Смета по сохранённому выбору

React отправляет `POST {card}/budget`. C# создаёт отдельную задачу и передаёт в `POST /v1/budget` снимок выбранного отеля, мест и цен. React опрашивает C# до итогового `budget.finished` и показывает состояние из `budget`.

В примере с 10 по 15 июня включительно для двух человек отель стоит 27 000 ₽ за все пять ночей, музей — 900 ₽ на человека, дополнительные расходы по оценке Python — 27 600 ₽. Питание составляет 16 800 ₽, городской транспорт 4 800 ₽, прочие расходы 0 ₽ и резерв 6 000 ₽. Итог карточки в C# составляет 56 400 ₽. При целевом бюджете 60 000 ₽ остаётся 3 600 ₽.

Если цена одного посещения неизвестна, итог показывает сумму известных расходов и помечается как неполный. Если Python не смог получить обязательную оценку, задача сметы завершается ошибкой. После изменения параметров или выбора старый расчёт помечается как `stale`. Новый расчёт использует актуальный снимок.

## 6. Повторы, таймаут и повторное открытие

| Ситуация | Ожидаемый результат |
|---|---|
| POST повторён с тем же ID и тем же телом | Python возвращает `202`. Ответ можно читать по прежнему `Location`. |
| POST повторён с изменёнными данными | Python возвращает `409 TASK_ID_CONFLICT`. |
| C# повторил GET | Возвращается тот же результат. C# применяет его один раз по ID. |
| Пользователь изменил карточку во время подбора | Результат для старой версии не меняет текущую карточку. |
| C# исчерпал срок ожидания | C# фиксирует таймаут и завершает ожидание для React. |
| Пользователь закрыл редактор | React прекращает опрос карточки. C# продолжает опрос Python и сохраняет итог. |
| Пользователь снова открыл редактор | Первый `GET {card}` показывает готовый результат либо возобновляет polling, если задача ещё `pending`. |

## 7. Отображение отсутствующих сведений

React показывает адрес, описание, звёздность, категорию и координаты, если данные соответствующего поля известны. При `imageUrl: null` или ошибке загрузки используется заглушка. Прочие сведения кандидата остаются доступны. Карточка направления показывает известные данные справочника. Дополнительные сведения, например часовой пояс, местная валюта и языки, зависят от согласованной схемы направления.
